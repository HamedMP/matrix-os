# Managed Chat and Bot attachment admission

Live subscription acceptance requires an exact PR bundle in an owner-authorized
runtime. Platform deployments preserve and verify the internal Clerk organization
required by Private Preview. A generic Preview503 does not establish model
attachment rejection. The normal Computers chooser includes owned private
runtimes using its compatible Preview category; `matrix preview list --json`
provides PR, confirmed bundle and expiry, and immutable release metadata provides
the full source commit. Check connectivity and per-Computer subscription grants
separately before submitting inputs.

Spec550 / ENG-265 restores explicitly submitted attachments for managed Pi Chat
and recipe Bot. Matrix AI is a presentation label; the observed authenticated
model descriptor decides image support. Linked ChatGPT subscription, owner API
and funded Relay remain distinct sources with existing source/grant fences.

The composer validates declared MIME/count/size before submission and preserves
unsent drafts on rejection. Gateway capture independently validates actual bytes
and exact owner upload paths. Missing/replaced or escaped uploads fail the
admitted turn before inference; submitted references remain in its transcript.
Only `temporary/desktop-chat/<filename>` uploads are accepted. The capture rejects
symlinks, hardlinks, directory identity changes and metadata/byte mismatches,
then keeps immutable bounded bytes for that owner/Chat/run/runtime generation.
Stop/completion/failure disposes the manifest. Files use random
`submitted-inputs/<uuid>` aliases through the existing artifact reader; the worker
gets no additional filesystem mount.

PNG/JPEG/WebP images reach Pi as native image content. Generic limits are four
images, two MiB each, eight MiB aggregate and eight attachments. Files are capped
at one MiB; text artifact reads retain192KiB. Binary chunk/hash support is not
universal PDF/Office text extraction. Funded Relay additionally caps images at one MiB aggregate decoded bytes under
its existing two MiB request limit. Other upstream sources may impose stricter limits.
The authenticated Bot bridge grants additional body budget only to recognized
native user image blocks; unrelated text, responses and global endpoints keep
their previous caps. Images become placeholders before session persistence.

Regression coverage must test the actual installed Pi loop, immutable file reads,
model input capability, grant/account revocation, owner/Chat/run/generation and
cancellation fencing, full image bridge/native peer transport, and session
save/load followed by another turn. A fixture response proves wiring, while live
acceptance needs the exact Preview backend plus Electron client and model source.

For Human Review, start a fresh managed GPT Chat, send a supported small image
with a clear visual question and a text file containing a unique marker, and
check their content in the reply. Follow up in the same Chat, reopen it and repeat
in Bot. Verify unsupported input retains the draft. Check Codex path/multiline
command expansion and exact copy before/after reload, then run a Bot task and
confirm one structured progress display with no plain Working footer. Record
immutable client/backend versions and the authenticated runtime selected.
