# Aoede Live: local developer guide

Status: implemented on `548-aoede-live`, **not provider-qualified or enabled for rollout**. This guide describes the current source, not proof of live correctness. Legacy Vocal transport/panel remain. `VOICE_HIDDEN` is still `true`; Live requires an explicit build-time preview opt-in. Do not deploy or publish this feature on the strength of fixture tests.

## Architecture and prerequisites

The shell uses native microphone capture and WebRTC directly to the speech provider. Gateway owner authentication, an existing authenticated `/ws` connection, owner Postgres, the installed app registry and canonical Chat are required. The platform mints funded sessions and observes billing on a trusted sideband. Neither browser nor gateway receives the provider API key. Speech credentials are machine/slot/current-epoch bound; there is no Gemini fallback or new browser event socket.

Use Node 24, pnpm and the existing developer setup. `bun run dev:full` launches the production-parity local environment; see `scripts/dev-production-parity.mjs` before starting/stopping it, and never stop somebody else's environment. **The current launcher's `platformEnvironment()` does not forward speech/Live environment variables.** Putting these variables in `.env` alone is not a working Live setup on `dev:full`. Explicit local process/container environment wiring and a shell built with the preview flag are needed; do not claim production-parity qualification until that path runs successfully. This documentation does not modify the launcher or authorize remote deployment.

## Configuration (three separate processes)

Keep credentials in local ignored configuration; never in shell public variables, screenshots or reports. No default price is encoded. Obtain the account's current rate and voice availability before enabling paid calls. One USD is 1,000,000 microUSD.

### Platform

Live requires the existing enabled OpenAI speech configuration in `existing_wallet` mode. Fixture and preview-no-charge configurations cannot fund Live.

| Variable | Required value/meaning |
| --- | --- |
| `PLATFORM_SPEECH_ENABLED` | `true` |
| `PLATFORM_SPEECH_PROVIDER` | `openai` |
| `PLATFORM_SPEECH_OPENAI_API_KEY` | Platform-only key; validated minimum length 16 |
| `PLATFORM_SPEECH_SECRET` | At least 32 UTF-8 bytes; distinct from the platform runtime signing secret |
| `PLATFORM_SPEECH_POLICY_REVISION` | Valid policy identifier |
| `PLATFORM_SPEECH_MODEL` | Existing transcription model; required even though Live has its own model |
| `PLATFORM_SPEECH_MICROUSD_PER_MINUTE` | Existing transcription rate; integer 1–1,000,000,000 |
| `PLATFORM_SPEECH_FUNDING_SOURCES` | Explicit comma-separated allowlist: `promotional`, `addon`, or both, no duplicates |
| `PLATFORM_SPEECH_MONTHLY_BUDGET_MICROUSD` | Positive integer speech monthly cap |
| `PLATFORM_SPEECH_MONTHLY_PROMOTIONAL_CREDIT_MICROUSD` | Integer 0 through budget; nonzero requires `promotional` |
| `PLATFORM_AOEDE_LIVE_ENABLED` | `true` (otherwise disabled) |
| `PLATFORM_AOEDE_LIVE_MODEL` | Exactly `gpt-live-1` |
| `PLATFORM_AOEDE_LIVE_VOICE` | Provider-supported lowercase voice identifier, 1–40 letters |
| `PLATFORM_AOEDE_LIVE_POLICY_REVISION` | 1–160 characters from letters, digits, `_ . : -` |
| `PLATFORM_AOEDE_LIVE_MICROUSD_PER_MINUTE` | Explicit Live rate, integer 1–1,000,000,000 |
| `PLATFORM_AOEDE_LIVE_MAX_DURATION_MS` | Integer 30,000–1,800,000; 600,000 matches the gateway's ten-minute default cap |

Do not set `PLATFORM_SPEECH_PREVIEW_NO_CHARGE=true` for Live. Invalid enabled configuration fails startup. Standard platform database migrations must run. Live uses its own fixed admission limits (16 global active operations, 10 owner admissions/minute), not the configurable transcription concurrency settings.

The gateway independently enforces a ten-minute default cap; the platform enforces its configured cap, and an observed earlier provider expiry shortens the session. Setting the platform to thirty minutes does not make the current gateway session thirty minutes long.

### Gateway

Reuse the speech runtime configuration:

- `MATRIX_PLATFORM_SPEECH_ENABLED=true` (also accepts `1`).
- `MATRIX_PLATFORM_SPEECH_ORIGIN`, falling back to `PLATFORM_INTERNAL_URL`: platform origin only, no path/query/credentials; HTTPS except loopback HTTP.
- `MATRIX_HANDLE`, `MATRIX_CLERK_USER_ID`, `MATRIX_MACHINE_ID`, `MATRIX_RUNTIME_SLOT` matching the platform's running machine record.
- `MATRIX_PLATFORM_SPEECH_RUNTIME_TOKEN`: existing speech runtime token, generated by the trusted runtime provisioning path for that machine/slot/epoch. A generic platform token is not interchangeable.

Preview identity overrides are restricted by the existing speech config loader; do not use them as an arbitrary local auth bypass. `createAoedeRuntime()` exposes unavailable routes when speech client, owner database, registry or Chat dependencies are absent. Owner Aoede tables bootstrap through the repository; the runtime borrows, rather than owns, the owner's DB pool.

### Preview shell

Set `NEXT_PUBLIC_AOEDE_LIVE_PREVIEW=1` **when starting the development shell or building the production shell**. A production bundle needs a rebuild; setting the flag only when restarting it cannot change the compiled value. The flag is off by default, including in production. Do not change `VOICE_HIDDEN` to qualify Live. The flag switches Desktop's overlay from retained Vocal to Live and exposes its dock button. Canvas uses the shared Desktop host; native mobile/Electron parity is not established.

## Invocation and actions

1. Sign in as the runtime owner and wait for the existing socket to connect.
2. Click Aoede in the dock. Opening the overlay only probes recovery; it does not mint a session.
3. Click **Start fresh session**. Browser microphone permission is requested before minting. Use a secure browser context (HTTPS or supported localhost), a working microphone and an allowed playback device.
4. Wait for the listening state; speak and inspect captions. **End session**, the close button or Escape stops local capture/playback and requests remote closure. Focus returns to the prior control. Reduced motion uses static styling.

No wake-word, automatic paid start or seamless reconnect is implemented. Do not document a Live keyboard/palette shortcut as qualified; the dock is the inspected entrypoint.

Direct actions use a deliberately narrow English transcript grammar. Examples of exact **transcript text**, not a guarantee that speech recognition will insert quotation marks:

```text
open notes
close notes
list apps
create note "Shopping" with "Buy milk"
append "Buy bread" to note "Shopping"
edit note "Shopping" replace "milk" with "oat milk"
remember I prefer short answers
list facts
forget "I prefer short answers"
```

Other requests go through canonical Chat, including requests that do not match this grammar. Ambiguous/uninstalled app targets must not produce a window effect. App open/close requires a correlated acknowledgement from the invoking socket after gateway registry validation. Notes writes use the actual Notes schema and locked SQL updates, preserving markdown and rich text; ambiguous titles/replacements or unsupported legacy rich text fail closed. Inspect the persisted note and its rendering rather than treating spoken output as write evidence. Facts retain the existing `~/system/vocal-profile.json` format and caps.

## Permissions, Chat and cancellation

Voice does not confer blanket permission. General work is admitted as the real owner into the durable Chat titled **Aoede**, using that Chat's current selection/interaction/permission modes. Busy work queues. Cards reflect canonical state, not fabricated build stages.

Only one current, explicitly low-risk approval whose question was presented in this session can accept an unambiguous complete voice decision. The shell submits through authenticated canonical approval HTTP; a socket frame alone is not approval proof. Medium/high/unknown-risk or destructive work needs an explicit UI decision. Cards offer **Allow once** and **Deny**, not session-wide permission. On an uncertain submission retry the same decision or inspect Chat before changing it.

`stop`, `cancel` (optionally `that`) targets one mapped task; ambiguous multiple tasks require selection. **Cancel task** targets its card. Accepted cancellation is not necessarily a confirmed terminal run. Closing voice does **not** cancel Chat; continue inspecting/approving/cancelling work in Chat after dismissal.

## Existing wallet funding and uncertain charges

Live uses `SpeechFundingPort` with isolated `speech:live` authority, existing `speech_operations`, the shared funded-AI wallet/ledger, and speech monthly allowance. There is no Aoede wallet or separate top-up flow: use existing Billing/wallet funding and an allowed promotional/add-on source. Speech counters are separate from text-model monthly counters. Allowance/grant terms freeze per machine for the UTC month; changed defaults apply at next reconciliation.

Before provider dispatch, the platform reserves:

```text
ceil((configuredDurationMs + 45,000) * LiveMicroUsdPerMinute / 60,000)
```

The hold includes bounded startup/finalization headroom, not an extra initialization debit. Insufficient eligible wallet balance or allowance rejects admission before provider dispatch. Cumulative usage updates replace snapshots; only trusted `session.closed.usage.seconds` establishes exact final usage. OpenAI's 15-second WebRTC initialization charge is credited against running duration, not added again. Consult the provider billing source below rather than inventing a rate.

After dispatch, lost creation responses, failed attachment/compensation and missing closure can charge conservatively to the reserved amount and retain an unconfirmed operation. Late closure can unblock admission but does not rewrite an already-conservative debit. An unresolved operation blocks another owner mint. Unknown provider IDs and usage beyond the reservation need operator/provider termination and accounting reconciliation. Do not delete operation rows, manually refund, or repeatedly remint to bypass that fence. Local duration timers are **not** a guaranteed provider dollar cap during a network outage.

## Recovery and privacy

Gateway capture is bounded to 24 recent text messages and 16,000 characters; startup seed is further trimmed to 12 messages/6,000 UTF-8 bytes. Only the latest owner's checkpoint is retained, for up to 24 hours; expiry runs on recovery/snapshot and an hourly sweep. Uncheckpointed speech can be lost. Gateway restart marks prior active sessions interrupted and attempts closure, not event replay or mutation replay. The user must explicitly start fresh with saved text.

**Delete saved voice text** calls the authenticated recovery deletion route and clears saved checkpoints/current gateway buffers. It is not deletion of durable Chat, facts, platform financial audit records, or captions already displayed in the browser. New speech can create new saved text. Matrix does not persist provider audio; mint sets `store: false`. This is not a claim about all provider processing/retention policies.

After the new invoking shell acknowledges readiness, runtime composition calls `seedRecentOutcomes()` with session-owned delivery authority and the prior session ID. It restores recent task cards from canonical Chat and watches pending runs without readmitting or repeating their work. This wiring has a regression test, but reconnect/restart restoration still needs live browser qualification. Open Chat to reconcile uncertain work; do not rerun a request just to recreate its card. Owner-authenticated GET snapshot exposes checkpoint/delegation metadata, but there is no dedicated recovery export UI.

## HTTP and socket contracts

All gateway routes use the existing owner principal/auth boundary and no-store responses:

| Route | Contract |
| --- | --- |
| `POST /api/aoede/session` | Strict `{ clientRequestId: UUID, sdp: string }`; 64 KiB body, SDP ≤60,000 chars; returns `{ sessionId, providerSessionId, sdp }` |
| `DELETE /api/aoede/session` | Strict `{ sessionId: UUID }`, 1 KiB; targeted/idempotent close, no stale-tab replacement close |
| `GET /api/aoede/session` | Latest session state/timing/finalization, recovery, delegation metadata and warning |
| `DELETE /api/aoede/recovery` | 1 KiB body limit; owner checkpoint deletion |

No client-supplied owner, funding, prompt or provider selection is accepted. Internal platform routes are `/internal/containers/:handle/aoede/session`, `/sessions/:id` for DELETE and `/sessions/:id/attach` for WS, with `runtimeSlot` query and speech bearer token. Attach also requires the persisted runtime/session binding and one controller claim; frames are capped at 512 KiB.

Existing `/ws` carries bounded `aoede:state`, `aoede:ui`, `aoede:card`, `aoede:approval_decide` and correlated client ready/result/cancel frames. Browser readiness/transcripts cannot authorize execution or settle money. Browser provider data-channel authority is restricted to `session.close`; delegation/context append stays trusted-sideband only. Duplicate request IDs must not create another billable invocation; changed payload under an existing ID conflicts. The shell does not automatically retry failed minting.

## Troubleshooting and qualification

| Symptom | Check / safe next step |
| --- | --- |
| No dock button / legacy panel | Public preview flag in the shell build/start process; production bundles need rebuilding with the opt-in |
| Start disabled | Existing owner socket connectivity/auth; reconnect before an explicit fresh start |
| Microphone blocked | Browser site permissions, secure context and OS mic permission; denied capture does not mint |
| Startup unavailable / 503 | Platform enabled wallet-backed config; actual env forwarding; valid runtime identity/token; gateway DB/registry/Chat composition; account Live availability |
| Listening never starts | Provider `session.started` ordering, WebRTC/network/playback; shell ends after a 20-second post-answer startup deadline; no auto retry |
| Conflict / cannot start again | Duplicate payload/invocation, competing owner session, admission limits or unconfirmed funded operation; inspect trusted platform state rather than bypassing it |
| App/note action unconfirmed | Invoking socket, installed registry, ambiguity and persisted Notes row/rendering; do not infer success from delivery or narration |
| Interrupted / missing cards | Start explicitly only after funding uncertainty is resolved; inspect durable Aoede Chat; restoration requires the new invoking shell's readiness acknowledgement |
| Captions text limit | Shell ends at 128,000 counted caption characters; visible captions remain, recovery has a smaller bound |
| Device/network changes | Current peer failure/track-ended/socket-epoch changes interrupt the session; select device/restore connection before starting fresh |

Read coarse server error classes locally; do not log or attach raw provider messages, SDP, credentials, private transcripts or identifiers to public evidence.

Focused source regression suites are `tests/platform/aoede-live.test.ts`, `tests/gateway/aoede/`, `tests/shell/aoede-live.test.ts` and `tests/shell/aoede-socket.test.ts`. For example:

```bash
bun run test -- tests/platform/aoede-live.test.ts tests/gateway/aoede tests/shell/aoede-live.test.ts tests/shell/aoede-socket.test.ts
```

SQL-dependent suites need their declared disposable Postgres setup; missing setup is not a passing qualification result. This documentation pass performed source verification only, no paid calls or browser testing. Local paid testing is authorized separately from remote deployment. Before rollout, collect real duration (at least six minutes), provider expiry/startup ordering, application-cap close, explicit/missing final usage and corresponding wallet outcomes, sideband loss with WebRTC alive, gateway/platform restart, transcript/delegation timing across roughly 20 utterances, old-delegation completion fallback, and Desktop/Canvas denied/recovery/approval/reduced-motion browser evidence on the production-parity path. Language, interruption, silence and device switching remain measurement requirements. Fixtures and short spike sessions do not establish any of these gates or SC-001..008.
