# Private model-history classification (ENG-355 / P3)

This optional owner-PostgreSQL layer is classification, not recipient consent, provider approval, or content deletion. It has no public endpoint, startup installation, history read, provider call, scheduler, or owned pool. Host composition must install the history gates before enabling the empty-chat birth hook.

`createGoogleModelHistoryStore(db, options)` exposes `migrate`, `inspect(owner,chatId)`, `inherit(owner,targetChatId,sourceChatIds,expectedRevision?)`, and the trusted creation callback `recordServerCreatedEmptyChat(tx,owner,chatId,receipt)`. The fourth optional `ChatRepository` constructor argument is `{ onServerCreatedEmptyChat }`; pass its four arguments directly to that callback. `withTransaction` preserves it. Absence preserves existing creation behavior and creates no birth metadata.

The ordinary boundary is the successful canonical empty-chat INSERT, its owner/member/state writes, and the birth ledger INSERT in one transaction. The creation module issues a private, single-use transaction/owner/chat receipt only while invoking that callback; old-row updates, idempotent replay, imported publication, JSON objects, and captured receipts after callback settlement cannot mint a birth. Ledger IDs are validated and capacity is capped at 200,000 total/10,000 per owner (configurable downward). Rows cascade only when their owning chat is actually deleted; metadata has no content-retention TTL that could erase classification. Current Google processing is personal-only; organization history remains unknown.

`inspect` returns `ordinary` only for a proven birth with no Google marker; a later Google marker always wins, including expired, purging, or deleted markers. Without a birth, even an available Google marker returns `unknown` with its Google context attached: fresh collection cannot certify earlier content. Legacy chats, preexisting opaque sessions, imports, archives and extracted assets need separate trusted migration/admission; no timestamp, absent marker, or content scan counts as ordinary proof. Birth also does not attest that a later opaque/native session is safe.

`inherit` rejects unknown/expired/purging/deleted sources or targets before content assembly, preserves all source origins and the earliest deadline through the existing GoogleContextStore, and requires an exact revision for an already Google-classified target. Ordinary references do not create fictitious Google origins. Closed markers cannot be revived. Available classification still requires current policy checks against the actual qualified provider at dispatch/release.

Pass the actual Kysely `Transaction` to the factory to join copied-content writes. The shared bounded transaction helper now reuses transactions instead of nesting them; SQL statement/lock timeouts (5s/2s) are set before the existing Google advisory lock (551035504), retained until caller commit/rollback. This is not a whole-transaction time limit. Host composition must use the same lock order and revalidate deadlines/current policy after additional awaits, immediately before content writes and dispatch. The helper never destroys a caller pool.

Creation was extracted from the oversized `chat/repository.ts` into `chat/creation-repository.ts` before adding this hook. Existing validation, conflict replay, members, read-state, hydration, outbox writes and transaction delivery are preserved. Further model-assembly work belongs in focused helpers rather than growing that repository: own history/resume, references, retry/queue snapshots, and broker session load/save need their separate integration tests. Owner detail inspection remains available; canonical inspection is not an AI transfer. Provenance handlers for saved transcripts, tool output, filesystem copies, imports, replay payloads, and deletion remain separate P3 units. No full-scope purge claim follows from this ledger.
