# Managed Pi saved-copy adapter (ENG-355 / P3)

This optional trusted composition adds `createGoogleManagedPiCopyHooks({ now? })` as the second argument to `createManagedPiSessionsRepository`. Existing uninstalled repositories keep their behavior. `load` and `save` accept an optional third `AbortSignal` after the existing executor. Caller input primitives are snapshotted before any new wait. This unit does not install the adapter at startup, schedule jobs, approve providers, or run against user data.

Installed access requires a genuine server-created empty-chat birth. Unknown historical/imported chats and closed/expired contexts deny access. The lock order is Google context (551035504), provenance global (551035503), exact registry copy, then session content. Both the actual session CAS and provenance registration join the caller's transaction or one new bounded transaction. SQL statement/lock timeouts are 5s/2s; cancellation checks after awaited operations roll the whole transaction back. The injected pool remains host-owned.

The versioned SHA-256 input is the bounded persisted PostgreSQL JSONB projection of owner, chat, session ID, row revision, messages, compaction flags, token estimate and runtime versions. Object key ordering is normalized by PostgreSQL; arbitrary-precision JSONB numbers never pass through JavaScript numeric parsing. At most `2 * BOT_SESSION_MAX_BYTES + 32768` bytes are hashed. No raw content enters the lineage registry or logs. Every current source origin is retained and the earliest context retention deadline is preserved. A bounded deterministic decision ID binds those originating consent decisions and deadline; it does not invent another owner retention choice.

Existing Google cache rows without matching lineage are denied on both read and save. A fresh Google cache row can register normally. A future explicit first-taint admission/reset seam is required when a previously ordinary cache becomes Google-derived; do not retrospectively certify its opaque contents from a current birth/marker alone. Reset must preserve canonical owner messages, fence stale workers and retain closed source-generation markers. This adapter does not implement that seam or qualify native/opaque provider resume.

`createGoogleManagedPiSessionDeletionHandler(db)` is a cache-only `session` purge handler for `mpi_${chatId}` entity references. The provenance worker already holds the registry copy lock. The handler only locks the owned session row, compares the same exact hash, and conditionally deletes owner/chat/session ID/revision in one transaction. Missing is idempotent; changed content or even a revision-only change stays modified/unresolved. Cancellation during lock waits or after DELETE rolls back. It never reads/locks context or provenance and never deletes canonical owner messages, unrelated sessions, files, imported objects, activity/outbox projections, or provider records. Completion covers only this registered Pi cache surface.

Before the transaction settles, the adapter captures the strict minimum of every observed Google context retention deadline, source expiry, and existing/new copy retention deadline. After awaiting its transaction promise it checks a finite current clock against that captured deadline and caller cancellation immediately before releasing loaded JSON or a save acknowledgement, without another database transaction. Cancellation/expiry during COMMIT can therefore withhold the acknowledgement of a save that already committed; it cannot undo that commit. Callers must reload under fresh authority rather than assume the write rolled back. When joining an outer caller transaction, the host retains responsibility for the equivalent final checks after its own commit and before final release; this inner adapter cannot wait for an outer commit while running inside its callback. Actual provider/current-policy admission remains separate.
