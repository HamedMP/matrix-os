## Obtain a portable operator workspace

```bash
gh pr checkout 3410
# From this PR checkout; choose a new private directory OUTSIDE any Git repository.
umask 077
export MATRIX_PREVIEW_OPS_DIR="$(mktemp -d "${TMPDIR:-/tmp}/matrix-preview-ops.XXXXXXXX")"
cp -R scripts/preview-pair/ops/. "$MATRIX_PREVIEW_OPS_DIR/"
cd "$MATRIX_PREVIEW_OPS_DIR"
python3 export-operator-state.py
python3 check-github-protections.py
```

Keep this directory until cleanup and restoration are verified; then remove it
or retain it in approved private operator storage. No file from Nima's computer,
bundle or private repository is needed. Requires Python 3, authenticated `gcloud`
and `gh`, Node 24+, Bun and a clean candidate checkout installed with
`pnpm install --frozen-lockfile`. Use your own normal Matrix control profile.

The export reads Cloud Run metadata and writes only the thirteen allowlisted
preview settings to `source-env.disabled.json`. API and worker must match, be
disabled/ready and retain the reviewed image, identity, worker roles and reader
binding. It does not read secret values, create a window or invent cleanup
proof. Files are exclusive, mode 0600, outside Git; rerunning into the same
folder stops rather than overwriting. Source settings include fixture and org
IDs: keep the exported files private. The four protected publishing references
are regenerated by name/version, never by reading their values.

If Source's image or configuration has changed, review that deployment first.
The scripts intentionally pin the last reviewed image digest and stop on drift.
Update and review the guard against the current deployment; do not roll back
Source or remove the check to get past it. Preserve other engineers' settings.

## Credential and IAM checks

```bash
python3 verify-source-token.py --candidate-sha "$MATRIX_PREVIEW_CANDIDATE_SHA" \
  --artifact-run <existing-run-with-an-unexpired-artifact>
# Optional: regenerate metadata-only diagnostic plans in a fresh exported workspace.
# export-operator-state.py --probes replaces the initial export command above.
python3 run-runtime-iam-probe.py
python3 run-publisher-iam-probe.py
```

The Source credential check reads only dedicated `matrix-pair-preview-source-github-token:1`
in memory. It verifies owner, current candidate, corrected controller and an
artifact-download redirect; it never downloads artifact bytes or prints the
credential. Review the reported expiry (originally November 22, 2026). Successful
reads do not establish the absence of excess fine-grained permissions. Hamed's
seven-day token must remain scoped to **HamedMP/matrix-os only: Actions read,
Contents read, Pull requests read, Metadata read**. Renewal is a separate
reviewed binding change: helpers deliberately reject versions other than 1.

`receive-source-github-secret.py` and `receive-clerk-secret.py` accept hidden
terminal input and store only their dedicated Cloud secrets. They are recovery
utilities; do not run them to overwrite working credentials. Never send keys in
chat. `github-control-secrets.py` defaults to checking the installed GitHub
protections and four enabled Cloud version references without reading values;
`--apply` copies only those four approved values over stdin to the protected
control environment. This is already installed and need not be repeated.

The two IAM probes create one uniquely named/labelled temporary job each, run
permission metadata checks as the actual preview identity, then delete only
that job after checking its label. No secret values are read by the probes.
Use `export-operator-state.py --probes` in the initial export to generate private
fresh inventory/plans (the public code contains no production secret inventory).
Check both success AND cleanup receipts. Reconcile pending jobs before retrying.
These tests supplement an effective/inherited IAM review; they do not replace it.

  -f name=CLOUD_RUN_SERVICE -f value=matrix-platform

The restoration example assumes the verified original was `matrix-platform`;
use the actual recorded original if it differed. Verify the variable readback,

## Bootstrap/recovery code and tests

`bootstrap/` preserves the remaining initial IAM, restricted-database, Clerk
fixture and bundle-access scripts for review/recovery. **Those resources already
exist. Do not rerun bootstrap during continuation.** These are imperative
historical setup programs, not an idempotent installer; database preparation
refuses existing targets. Database finish requires its actual failed-bootstrap
receipt. They are included to preserve the implementation, not to reconstruct
or fake historical receipts. Copy the necessary files into the private workspace
only for a separately reviewed recovery operation.

Portable bootstrap dependency resolution uses `MATRIX_PREVIEW_CANDIDATE_ROOT`;
Clerk bootstrap additionally requires reviewed `MATRIX_PREVIEW_CLERK_INSTANCE_ID`
and `MATRIX_PREVIEW_CLERK_ISSUER`. Bundle inspection requires the reviewed exact
`MATRIX_PREVIEW_BUNDLES_ENDPOINT` and only checks `matrixos-bundles`. IAM apply
uses the corrected pin but is not a pin-rotation command; its publisher phase
creates the pool/provider and stops if they already exist.

The old personal device-login/two request drivers are superseded by normal
Matrix login and `preview:pair:create`; old GitHub admin bootstrap is superseded
by the installed protections and current read-only checker. No credentials,
personal identity data, live receipts, inventories or captures are in this PR.

Run each test file explicitly (hyphenated filenames are not unittest discovery
modules):

```bash
for test in test-*.py; do python3 "$test" || exit; done
```

These offline guards do not qualify live Cloud, migrations, identity flow,
Electron or collaboration behavior. Keep the PR draft until human review;
continue via the PR checkout, **without a main merge**. No public product
behavior changed; a companion documentation-site change is not required for
this internal operator handoff.
