## Native no-paid fixture and limits

Run `CODEX_SPIKE_BINARY=/absolute/path/to/exact/codex python3 specs/532-codex-0157-contract-qualification/evidence/probe-patch.py`. Temporary data and processes are cleaned on exit, including exceptions during initialize: terminate/wait/kill child and close selector/stdin/stdout/stderr. Run the same command with `--verify-init-cleanup` to force an initialization exception against a real throwaway child and assert every resource closed. This control failed before cleanup repair (`Failed initialization left child running`, exit 1) and passes afterward (exit 0); its RED case explicitly cleans the deliberately leaked child too. Native metadata traffic outside the fake inference endpoint may still occur; this is not a network-isolation proof.

The earlier c589 fixture did not associate its read with the `turn/start` returned ID. Its loaded-resume A result could therefore be the previous turn; that historical A/A/C claim is invalid as lifecycle proof. Deterministic stale-read controls failed before repair: previous completed → new inProgress → new completed incorrectly returned the previous turn, and previous-only never timed out. All three calls now require their own started turn ID.

The exact-ID-only experiment then exited 1 twice: first at fresh turn, next at loaded turn, with exact-ID `thread/read` status interrupted, completedAt null, error null, no items, before any request for that turn reached the fake Responses endpoint. These are **read projection observations**, not independently established runtime terminal failures. Tagged [thread_processor.rs:2879–2900](https://github.com/openai/codex/blob/rust-v0.157.1/codex-rs/app-server/src/request_processors/thread_processor.rs#L2879-L2900) samples live agent status and [lines 5766–5779](https://github.com/openai/codex/blob/rust-v0.157.1/codex-rs/app-server/src/request_processors/thread_processor.rs#L5766-L5779) converts reconstructed inProgress turns to Interrupted when the sampled thread is not active. This projection does not add completion metadata. Actual terminal [turn/completed emission](https://github.com/openai/codex/blob/rust-v0.157.1/codex-rs/app-server/src/bespoke_event_handling.rs#L1321-L1345) binds thread and turn ID; [TurnComplete handling](https://github.com/openai/codex/blob/rust-v0.157.1/codex-rs/app-server/src/bespoke_event_handling.rs#L1504-L1528) provides the real completion metadata.

A failed/interrupted actual completion stays a failing assertion. There is no sleep-based terminal override or retry of a failed inference turn. Synthetic controls cover notifications before the RPC response, notifications after the response in the same chunk, wrong-thread/previous-turn events, stale-only timeout, projection status before completion, real interrupted completion, and notification bounds.
