# Published Codex 0.164.0 qualification

The [scheduled Codex Provider Contracts run](https://github.com/HamedMP/matrix-os/actions/runs/39939293051) resolved `@openai/codex@0.164.0` and both native targets intentionally failed at `Codex 0.164.0 is not verified`. This maintenance admits only that exact published version in the paired exec and app-server contracts. It does not promote the installed customer CLI or enable new upstream API methods.

## Published artifacts and full delta

- [Official release](https://github.com/openai/codex/releases/tag/rust-v0.164.0), October 23, 2026. `pnpm view @openai/codex version --json` returned `0.164.0`; the exact package reports `codex-cli 0.164.0`.
- [Tagged exec JSONL source](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/exec/src/exec_events.rs): SHA-256 `dafa872d7e86a099e56e28a329dcb9c03db90ed768c3b88cca8c91d46dc1d0e5`. It is byte-identical to the retained 0.163.0/0.158 fixture. All eight required event names remain present; the exec parser contract is unchanged.
- Published Linux x64 `app-server generate-json-schema --experimental` output: 902,186 bytes, SHA-256 `92fe055424a3709999a05baae615be9e1e1e0b127e033cace6849b2ea785ea07`. The exact generated bytes are retained at `tests/fixtures/codex-0164/app-server-schema-0164.json.gz`. The scheduled run's independently generated Darwin arm64 schema reports the same digest and the same three changed notification digests.
- The 0.163.0-to-0.164.0 regression removes only the reviewed additions and compares the entire remaining generated JSON tree, including all referenced definitions, to the exact 0.163.0 fixture. Existing server request and notification method sets are unchanged. Three client requests were added: `thread/sample`, `thread/sample/cancel`, `feedback/save`.
- Eight v2 definitions were added: `ApplicationStorageRequirements`, `FeedbackSaveParams`, `FeedbackSaveResponse`, `ImageGenerationInputImage`, `ThreadSampleParams`, `ThreadSampleResponse`, `ThreadSampleCancelParams`, `ThreadSampleCancelResponse`.
- Optional fields were added to application storage requirements; pre/post-model managed hooks; MCP server tool-list metadata; prediction-mode fork MCP selection; realtime voice session ID; and turn start/steer Responses metadata patches. `HookEventName` adds `preModelRequest` and `postModelRequest`; `PlanType` adds `sci` and `sci_plus`. Descriptions changed for prediction-mode fork config and turn start/steer metadata replacement semantics. The retained public Settings-auth graph differs only by those two additive plan enum values; initialize/login/read/cancel request variants and login-completed notification remain byte-equivalent to 0.163.0.
- The image-generation `ThreadItem` variant now accepts either `fileId` or `result`, adds optional `inputImages`, and no longer requires `result`. Its changed transitive payload shape updates the required `item/started`, `item/completed`, and `turn/completed` digests. The other eight consumed RPC digests are unchanged. Matrix's artifact extractor still uses an available saved path or inline data; an opaque `fileId` alone yields no fabricated file path or attachment. The regression tests this boundary.

No existing required field changed except the image-generation result requirement. Matrix does not call the new sample/feedback requests, use the new metadata patches or hook types, or treat a file ID as a path. The separate Settings login allowlist now admits only exact 0.164.0 after its public auth schema review; this is covered by synthetic end-to-end Settings admission and native-account commit tests, not a claim of live OAuth/device login. No runtime parser, approval or sandbox policy change is needed.
