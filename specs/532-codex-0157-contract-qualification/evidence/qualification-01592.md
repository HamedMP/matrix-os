# Codex 0.159.2 provider contract qualification

The [baseline failed workflow](https://github.com/HamedMP/matrix-os/actions/runs/36659395635) installed published `@openai/codex@0.159.2` on both `linux-x64` and `darwin-arm64`. Both target verifiers stopped at the intentional unknown-version guard before admitting the patch. This failure blocks the independent Jev stack's CI.

## Exact upstream artifacts

- Official [tagged exec source](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/exec/src/exec_events.rs): SHA-256 `dafa872d7e86a099e56e28a329dcb9c03db90ed768c3b88cca8c91d46dc1d0e5`, identical to the qualified 0.159.0 source and the checked-in `tests/fixtures/codex-0158/exec-events.rs`.
- Actual published experimental app-server schema generated by both baseline jobs: SHA-256 `7243ba241962af92ca60581f1a81808ebda4212a800f8b205f54703bcfd508c5` on each target. The full bytes match the qualified 0.159.0 fixture at `tests/fixtures/codex-0159/app-server-schema-0159.json.gz`; equality of the whole digest includes nested referenced definitions, not just method names.
- All 22 recorded target/method digest rows (five required server methods and six required notifications on two targets) match the existing qualified digests. No Matrix-consumed request or notification payload changed.
- Independent local darwin-arm64 generation with the exact published 0.159.2 CLI produced the same full schema SHA-256 and matched the pinned 0.159.0 fixture byte-for-byte. The real verifier accepted the official tagged exec source and that generated schema as 0.159.2.

## Native no-paid probe

The exact published darwin-arm64 0.159.2 CLI passed the repo-owned isolated app-server/MCP fixture: fresh turn A, loaded resume retaining A, and cold-process resume C each completed with one scoped MCP call. This uses synthetic credentials and a local fake Responses endpoint. The probe does not establish real provider or Gmail acceptance and does not change the known loaded-session registration replacement limitation.

## Scope and gates

The regression first rejected 0.159.2; this patch adds only its explicit records and advances both latest-verified pointers. Earlier versions remain recorded, 0.159.1 stays unverified, and unknown newer versions remain denied. The customer installer/runtime pin stays at 0.156.1. No provider account, authorization, Gmail or Jev implementation changes are included.

The baseline workflow's already generated artifacts establish upstream provenance and semantic equivalence; they do not substitute for the proposed head's full CI, exact-head review or both-target provider workflow. Record those outcomes on the PR before merge.
