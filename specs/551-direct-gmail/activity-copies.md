# Registered activity copies — ENG-355

`createGoogleActivityCopyAdapter(db,{now?,quiescence?})` supplies `migrate()`, an optional `ChatRepositoryOptions.activityWrites` hook, `delete(input)` for the purge worker and `quiesceCopy(ownerId,entityRef,signal?)` for host scheduling. Migrate after Chat/history/provenance bootstrap; it adds nullable `chat_run_events.google_redacted_hash` for durable redaction idempotency. The factory owns no pool, timer or scheduler. Startup installation is a separate parent integration gate.

Activity persistence is extracted into a focused helper. Before content locks, the hook acquires owner context/birth, provenance global 551035503, and sorted `derived/gae_${activityId}` registry copies. Discovery is bounded to 500 stored plus 100 requested IDs and is rechecked after chat/run locks. Existing opaque activity without lineage fails closed; first Google taint needs explicit host reset/admission rather than retrospective certification. Terminal-binding activity insertion uses the same fence. Known ordinary chats create no Google registry copies, while absent hooks retain legacy behavior.

Exact versioned hashes use persisted PostgreSQL JSONB text, owner/chat/run/activity identity, run-local sequence, occurrence timestamp and the entire typed event. Input is capped at 64 KiB per event and 8 MiB per run load. Hashes and all mixed source origins/earliest originating deadlines are registered in the actual content transaction. Transitions update exact registry revisions; evicted event copies remain idempotently missing for later worker settlement. No message body or credential enters registry/logs. Cancellation and captured deadlines fence both final SQL and actual outer-COMMIT acknowledgement/live-batch release.

The deletion handler performs no context/registry lookup or dispatcher wait. Under exact owned private chat → run → event locks, an active run returns unavailable. A terminal run permits atomic hash/xmin-conditional replacement with a content-free typed run-status event matching the terminal run status. Event ID, run sequence, occurrence time, canonical user messages and other runs remain intact. A stored expected-hash marker plus exact tombstone verification makes interrupted-COMMIT retries idempotent without declaring modified payload deleted. Missing rows are idempotent; changed, shared, active or malformed rows remain unresolved. Abort checks cover row waits, mutation and post-COMMIT return.

Host scheduling must stop and drain dispatch BEFORE calling `executeClaim`: waiting for an admitted writer while the worker holds its registry copy can deadlock. For expired/closed sources, guarded `finishRun` cannot serve as cancellation cleanup. The optional trusted `quiescence.withStoppedRun({ownerId,chatId,runId,signal},work)` must verify durable owner/source purge admission, stop and drain real dispatch, prevent new work and hold that authority until `work` settles. No owner/client boolean is accepted. `quiesceCopy` calls this guard before content-free, atomic run/turn/chat lifecycle updates; it never alters event/message payloads or their hashes. Missing or declined admission denies. Root composition must emit content-free invalidation after successful lifecycle settlement, and must permanently block stale source work; SQL terminal state alone does not stop external computation. Call this seam before worker claims, never from inside a deletion handler.

Worker composition must dispatch `derived` refs by exact namespace: `gae_` to this adapter, `cm_` to canonical-message redaction, and unsupported kinds to unresolved. Existing `queueExpired`, `claimPurge`, `executeClaim` and cleanup remain host-scheduled bounded APIs; no complete account/provider purge follows from one adapter. Assistant preview repair remains the parent's canonical redactor responsibility. Run/queue context snapshots, attachment metadata/file bytes, historical outbox payloads, imports/files and infrastructure/provider copies remain separate coverage gates.

Synthetic native PostgreSQL tests cover atomic registration/rollback, transitions/hash normalization, modified/missing lineage, owner isolation, terminal bindings, first-taint denial, actual COMMIT abort/expiry, idempotent real-worker deletion, 500-event eviction, worker/write lock competition, row-wait cancellation and trusted pre-claim quiescence. Ordinary repository behavior and metadata-only outbox parity are verified separately.
