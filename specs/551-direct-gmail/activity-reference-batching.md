# Activity references and bounded reads (ENG-355, PR 2840)

Valid activity IDs can contain dots and colons. Existing alphanumeric/underscore/hyphen IDs retain `gae_<id>`. Punctuation IDs use `gae__<SHA-256 of exact ID>`, within the provenance 160-character limit. The extra underscore cannot collide with a legacy reference because a valid activity ID begins with an alphanumeric character.

`chat_run_events.google_activity_entity_ref` is nullable lookup metadata with a partial unique index. The writer fills missing punctuation mappings in one conditional batch only after validating existing copy lineage or exact ordinary proof, completing the content write, and hashing the owned rows under content locks. The mapping is excluded from the content hash. It never certifies content or provider approval. Unproven historical punctuation rows do not receive a retrospective mapping.

Redaction and pre-claim quiescence resolve a hashed reference through this index and exact owner join, then verify the actual ID computes to the requested reference. They never interpret a digest as an event ID or scan all owner events to guess a match. Missing hashed mappings remain unavailable/unresolved, including after physical row removal; a false deletion receipt is worse than incomplete coverage. Existing safe-ID missing handling is unchanged. Forged/ambiguous mappings fail closed before content deletion or runtime stopping.

Activity writes now lock/read at most 600 exact copy references in one sorted query, match at most 500 ordinary receipts in one query, and retire adopted receipts in one query. The held context lock prevents concurrent classification changes; current classification is rechecked before content, after content and once before COMMIT. Captured deadlines and cancellation are still checked through the row loops and after actual COMMIT. Initial or changed Google-copy registration continues to use the existing bounded per-copy store; this change does not claim constant SQL for registering 500 changed copies.

Native PostgreSQL tests cover punctuation including 128-character IDs, exact-owner lookup, legacy refs, missing/forged mappings, refusal to certify old content, worker/write locking, cancellation, expiry, and a 500 unchanged-copy SQL budget (at most 80 queries; previously 5,537), followed by another owner's admission. No external calls, user files, provider approval, startup installation or deployment occur in this unit.
