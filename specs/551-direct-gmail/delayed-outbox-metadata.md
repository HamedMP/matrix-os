# Delayed canonical event metadata — ENG-355

The bounded `ChatRepository.replayOutboxWindow` SSE path selects cursor, owner, chat, revision, event type and timestamp plus a constant empty JSONB payload. It does not materialize stored assistant text, preview, activity or credential projections. Cursor validation, owner filters, the 100-event cap, gap detection and checkpoints remain unchanged. `replayOutbox` retains its separate explicit owner inspection behavior; detail inspection and export remain available through their existing owner checks. This change does not erase stored outbox payloads or qualify raw replay as model input.

During SSE attachment, buffered live commits now copy only scalar event metadata with an empty payload rather than retaining a mutable event/content reference. The existing 200-event buffer cap, subscriber caps/expiry and shutdown remain unchanged. Both persisted replay and attach-buffer delivery still call `deliver(..., false)`, so even a content-negotiating subscriber receives notification frames and refetches through current owner reads. Ordinary negotiated immediate live content delivery is preserved. Metadata contains opaque identifiers/revisions rather than message bodies; no new provider calls, database pools, caches or timers are introduced.

This is separate from the post-COMMIT live batch lease gate. It does not supply canonical message redaction, persistent outbox payload retention/deletion, or coverage for finishRun, attachments, activity events or run/queue context snapshots. Other content-bearing writers must acquire their own same-transaction provenance and release checks before the optional Google-copy writer can be installed. Files, artifacts, imports and infrastructure/provider copies remain separate scopes.

Validation uses synthetic native PostgreSQL fixtures to prove SQL replay-window minimization, unchanged raw owner inspection, owner isolation and persisted-payload preservation. A deferred attach test proves metadata is snapshotted before source-event mutation and content is withheld on replay. Existing SSE/live-content, backlog/cursor and bounded-buffer tests exercise ordinary parity.
