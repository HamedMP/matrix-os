# Managed Google-data route descriptor foundation

ENG-355. This unit adds a private strict descriptor and a pure comparison against existing dispatch configuration. It installs no relay or broker guard, changes no lease, approves no provider, and is not managed Google-data runtime qualification. The currently used default Anthropic route remains a separate integration gap.

The first adapter recognizes only the existing Cloudflare Workers AI path: the same validated gateway configuration determines Cloudflare account and gateway ID, `mapFundedModel` determines canonical/native model, `workersAiTarget` determines the exact model-specific upstream URL, and the actual configured Workers AI API token supplies its private SHA-256 fingerprint. Its generation comes from an explicit operator record bound to that fingerprint. Temporary Matrix-funded credentials and unused gateway-auth tokens cannot supply upstream credential identity.

The descriptor binds a stable private route ID/revision, exact HTTPS relay endpoint and client API, exact upstream endpoint/API/model, Cloudflare account/gateway and credential mode, stable upstream credential generation/fingerprint, ordered reviewed recipient chain, request-control policy version and expiring evidence digests. Account-settings evidence is explicitly operator supplied; the pure builder cannot inspect account billing, provider retention or onward processors. It does not infer a recipient from a model vendor's name or claim Cloudflare Workers AI has ZDR. Reviewed bounded retention remains a separate Matrix policy decision.

Canonical wire serialization uses strict schema property order while preserving recipient order. The digest is SHA-256 over `matrix-managed-google-route:v1:` followed by that serialization. Unknown fields, changed actual route/credential, missing or expired review, mismatched recipient/account/endpoint, unsupported API/model and implicit Anthropic selection produce no descriptor.

## Remaining integration seams

- Bind the exact descriptor digest and advertised relay endpoint into newly issued qualified leases, persisted verification/control responses and cache identity. Today the gateway supplies `relayBaseUrl` locally from `MATRIX_FUNDED_AI_RELAY_URL`; the strict legacy issuance response does not bind it or a descriptor. Old/class-fallback leases may serve ordinary traffic only, never qualify Google processing.
- Keep full private descriptors out of model-visible results, signed collection headers and small policy-request bodies. The bounded 16-recipient descriptor can exceed the existing 16 KiB policy request cap; integration needs digest-based trusted lookup or an explicitly revised bounded internal transport.
- Build from the same immutable configuration/model selected for dispatch and compare the bound digest again immediately before every proxy send, queue retry and result release. A descriptor helper alone cannot prevent rerouting or remote account changes.
- Resolve broker identity from the qualified lease's stable downstream descriptor, never the temporary funded token hash. Match that against reviewed processing profiles and owner consent; do not seed approval.
- Review actual account terms/settings and complete onward recipient evidence, with explicit expiry/revalidation. The reference Bedrock PR 2624 has region/inference-profile routing and settlement provenance; that is not stable upstream account/credential proof. Do not duplicate or merge its transport here.

## Anthropic selection through Cloudflare

Official [BYOK documentation](https://developers.cloudflare.com/ai-gateway/configuration/bring-your-own-keys/) supports `cf-aig-byok-alias` on provider-native passthrough requests. The [Unified Billing documentation](https://developers.cloudflare.com/ai-gateway/features/unified-billing/) documents `cf-aig-no-wholesale: true` to prevent Unified Billing fallback. A later explicit named-BYOK adapter can use both controls and separately bind/revalidate the actual selected key generation, account and evidence. An alias is not proof that its credential cannot rotate.

The documented precedence remains request provider key, default stored BYOK, then Cloudflare-managed Unified Billing. No documented force-Unified-Billing request header was found. Calling `/ai/v1/chat/completions` alone does not bypass default BYOK. A future Anthropic Unified Billing adapter therefore needs reviewed, current account-state evidence and a fail-closed revalidation mechanism; today's implicit no-provider-key request cannot establish it. Cloudflare documents ZDR only for its managed Unified Billing credentials, independently of Gateway logging, rather than for all BYOK or Workers traffic. No live account observations are embedded in this public-safe document.
