# Managed Pi stop authority — ENG-355

Managed Pi exposes server-only `stopAndDrain({ownerId,chatId,runId,signal,...optionalExpectedRuntimeTuple})` and `withStoppedRun(input,work)`. The runtime derives the exact runtime handle and execution generation from its own observed admission; request fields, model text and canonical terminal status cannot create stop authority. Unknown, foreign, expired, restarted or uncertain runs deny. This is actual runtime behavior, not an uninstalled interface: broker inference is cancelled, the owned supervisor worker is forcibly stopped, its exact unwrapped stopped ACK tuple is validated, and the actual execution promise (including tool and worker release cleanup) drains before retention work can run. Cancel delivery alone and the ordinary cancellation grace period do not qualify. Early output-generator return also awaits this drain; shutdown awaits execution and running retention work or reports uncertainty.

The host must acquire the shared `ExecutionAdmissionFence` and durable Google source/context purge fence before calling this API, and hold them through the complete copy operation. This unit does not install that host composition, alter the canonical orchestrator, or qualify non-managed/background adapters. Separate adapters need their own observed stop authority. Retention work must remain a finite, bounded trusted database operation; a callback is not permission to restart execution or call a processor.

Receipts contain only version, owner/chat/run, exact runtime/generation and observed stopped time. A trusted injected `onStopped(receipt)` sink is awaited after actual execution and worker ACK, before retention work. It supplies the seam for durable owner-Postgres receipt persistence. No durable receipt repository or post-restart receipt authorizer is installed here: the host must separately bind and verify persisted receipt identity before later erasure. Never infer it from `run.status='failed'`, missing in-memory state, or a caller-supplied receipt. In-memory proof expiry cannot establish safe deletion days later; missing durable proof remains an explicit blocker.

Process-local metadata has a default 1,024-row cap (maximum 4,096), 15-minute terminal TTL (maximum one hour), recurring cleanup at most every minute, bounded 30-second drain (maximum one minute), and shutdown timer/metadata cleanup. Active uncertain executions count toward the cap rather than being evicted as if stopped. A timeout or caller cancellation withholds work; late execution settlement may produce a real receipt but cannot retroactively release a refused callback. The host owns all shared pools and dependencies.

Tests first reproduce absent stop authority and premature generator return. Local real Unix-socket client regressions cover raw supervisor failure, mismatched handle/generation, delayed worker ACK, actual deferred execution, cancellation, uncertainty, TTL/caps, owner substitution, durable receipt capture and shutdown. These checks use synthetic data and establish no live worker/device, Google recipient or deployed retention qualification. Public product documentation remains the existing separate site documentation deliverable linked by ENG-355.

Native ACK qualification is a separate required prerequisite: the existing systemd launcher can skip Stop on `is-active` exit3 while a unit is transitioning. The next bounded launcher unit must unconditionally stop the exact trusted unit and verify terminal state/task absence; this adapter's tuple comparison cannot repair a false supervisor ACK. Do not enable retention qualification until that underlying stop proof and the durable host composition are installed and tested.
