# Canonical assistant delta copies — P3 foundation

ENG-355: https://linear.app/matrix-os/issue/ENG-355/prepare-gmail-oauth-verification-and-casa-evidence

This bounded unit extracts `appendAssistantDelta` from the oversized run lifecycle repository into `chat/assistant-delta-repository.ts` before adding behavior. `ChatRepositoryOptions extends ChatCreationOptions` adds optional `assistantDeltaWrites`; transaction-scoped repositories preserve that option. `createGoogleCanonicalMessageWriteHook({now?})` supplies the private hook. `appendAssistantDelta(owner,input,signal?)` keeps cancellation separate from content. No hook is installed by default or at startup.

The installed hook snapshots owner/chat/run/message/input primitives before waits and clones validated encrypted sidecars. It requires personal, known-birth, available context; a published collaboration scope is denied even if `chats.collaboration` is null. It acquires context/birth fence 551035504, provenance global 551035503, the exact `derived/cm_${messageId}` registry copy, then chat, run, message and at most sixteen sidecar rows. Actual content mutations and exact-revision provenance registration share one transaction. Statement/lock timeouts are 5s/2s before locks; the host owns the database. No pool or timer is created or closed.

A versioned SHA-256 input uses persisted PostgreSQL JSONB text: owner/chat/message/run/turn/sequence identity, assistant parts, search text, byte count, and encrypted sidecar identity/offset/length/envelope. Hash input is capped at 512 KiB; individual sidecar envelopes are bounded before aggregate hashing. JSONB object keys are normalized without JavaScript numeric parsing. Lifecycle state/timestamps and the credential reveal UI flag are excluded. Search, byte count and encrypted envelopes are payload: changing them invalidates the saved hash. No raw message, credential or envelope enters the registry or logs. User messages are never registered or modified by this helper.

Every source origin is retained. The effective copy deadline is the strict minimum of context retention, source expiry and an existing copy deadline; a deterministic bounded decision ID binds originating consent decisions rather than inventing another owner choice. Stream appends and snapshot recovery update the exact registry revision atomically. An identical snapshot/payload with unchanged origins/deadline does not churn its copy revision. Conflicting recovery prefixes, modified hashes, purge tombstones and closed/expired sources roll back. Existing Google message payloads without a matching registry copy deny; an explicit first-taint admission is required for any future registration of preexisting assistant content.

The captured strict deadline and cancellation are checked again after the transaction returns, without another classification query. A committed write can have its acknowledgement withheld if cancellation/expiry occurs during COMMIT; callers must re-admit/reload rather than assume rollback. The hook registers a trusted synchronous `() => true` release check on the actual outer ChatRepository transaction, including through nested repositories. The shared bounded outbox batch seals before COMMIT; after COMMIT settles, all registered checks pass before any sink sees any event or the outer acknowledgement returns. Cancellation or expiry withholds the entire mixed batch. SQL rollback performs neither checks nor delivery. The ledger caps events and checks at 100 each and active/committing batches at 128, and clears closures/content on every settlement without closing the host pool. A guarded transaction-scoped repository without the exact active owning ledger fails closed. Ordinary unchecked repositories retain their existing delivery behavior. This hook classifies saved copies and does not authorize the actual AI provider or establish processor compliance.

## Installation blockers

This is not a complete canonical write or deletion adapter. `finishRun` can replace/finalize payload and recalculate byte count; assistant attachments, activity transitions/eviction, run/queue snapshots, search/preview redaction, credential deletion and replay copies still need their own same-transaction coverage. The delta/snapshot live outbox batch now shares the post-COMMIT release gate; this does not qualify other writers or persisted replay payloads. Event-stream replay and delayed attach-buffer delivery already emit metadata only. `publishCommittedExternalOutbox` bypasses the transaction ledger and must remain metadata-only (current collaboration callers emit empty `chat.updated` payloads). Sink calls are synchronous: the gate withholds the whole batch before the first send, but cannot retract bytes already handed to a sink.

No purge handler, scheduling, startup enablement, deployment or all-copies completion claim is included. A future redactor must preserve owner rows, IDs/sequences and links, compare owner/hash under content locks, remove owned encrypted sidecars and derived projections atomically, and emit content-free invalidation after commit. Files, artifacts, imports, opaque sessions and processor/infrastructure copies remain separate unresolved scopes. Public documentation and live qualification remain the parent plan's separate deliverables.
