# Run and queue context snapshots — ENG-355

`createGoogleContextSnapshotAdapter(db,{now?,quiescence?,queueAdmission?})` supplies `migrate()`, `write`, `delete(input)` and `quiesceCopy(ownerId,entityRef,signal?)`. Install the private hook through `ChatRepositoryOptions.contextWrites`, after Chat/history/provenance bootstrap and this migration. No startup enablement is included. Migration adds nullable `google_context_redacted_hash` to run/queue rows for exact-hash redaction retry; the adapter owns no pool, timer or scheduler.

Admission, retry, personal queue enqueue and claim enter this hook before existing helpers lock content. The focused `context-write-hook.ts` contract/input snapshot helper and a narrow repository composition seam keep context behavior outside the oversized repository/queue implementation; existing algorithms remain unchanged. A transaction-scoped repository calls the original operation with only this outer hook disabled, retaining birth/message/activity/outbox options and the exact transaction-owned release ledger. This is the extraction plan for this layer; no new behavior is added inside the oversized queue class. Private, server-created known-birth chats are required. Absent hooks preserve legacy behavior.

The fence orders context/source → provenance global → sorted exact registry copies → private chat → existing run → queue. Queue claims discover at most 20 queued IDs; idempotent admission also resolves the actual stored identity by request ID so a new requested ID cannot bypass an old snapshot. The bounded set (at most 45 keys) is rechecked after lock waits. Missing Google lineage, closed source, modified payload, ambiguous claimed run or set changes fail closed. This helper does not retrospectively certify first-taint snapshots; separately reviewed ordinary-copy receipts may prove an exact earlier ordinary hash.

`derived/grc_${runId}` and `derived/gqc_${queuedTurnId}` hashes cover exact persisted JSONB context plus version, owner/chat/kind/entity identity. `contextSnapshotPayloadHash(tx,{owner,chatId,kind:'run'|'queue',id})` exposes the identical owned-row hash for trusted composition; caller owns the source/provenance/chat fences. The schema caps context at 64 KiB, SQL suppresses raw oversized bodies before returning them (80 KiB normalized JSONB, 96 KiB hash projection). Request hashes, run lifecycle, queue status/position and owner-written queue parts are excluded from the copy payload. Same-transaction registration retains every mixed source and the earliest originating/context/existing-copy deadline. Actual outer COMMIT gates acknowledgement and the entire live batch; no extra classification transaction races release.

Cancel, reorder and owner edits do not rewrite `context_snapshot`; their existing registry hash/deadline remains valid. Cancellation does not erase context. Current queue code has no independent eviction write; actual owner Chat deletion cascades rows and makes their registered copies idempotently missing. Claimed queue history assembly creates a separately registered run copy in the same transaction, preserving its queue source registration.

The worker handler uses copy → exact private chat → stopped run → queue/content row ordering. It clears only `context_snapshot`, writes an expected-hash marker under owner/hash/xmin conditions, and preserves IDs, owner messages, queued parts, request hashes and unrelated metadata. NULL context plus matching marker is idempotent deleted; modified/oversized/shared/active/queued/uncertain claimed rows remain unresolved. It never stops dispatch, reads source authority or acquires registry locks inside a worker callback. Callback routing must separate `grc_`/`gqc_` from `cm_`/`gae_` and reject unknown namespaces.

Before claims, `quiesceCopy` requires trusted durable admission: run copies use `quiescence.withStoppedRun({ownerId,chatId,runId,signal},work)`; queues use `queueAdmission.withStoppedQueue({ownerId,chatId,queuedTurnId,signal},work)` to prevent/drain claims. A claimed queue also requires the actual stopped-run authority. These host callbacks verify owner/source purge admission and real runtime stop/drain, hold their fences through lifecycle SQL, and never accept client booleans. Metadata-only SQL then aborts active runs/turns and cancels/compacts queue positions without changing snapshot hashes or owner intent. Missing/declined/cancelled admission denies. Call before `executeClaim`, never while a worker holds its registry copy lock. Root composition must emit content-free invalidation and provide exact runtime binding/ACK evidence; database terminal status alone does not stop external computation.

Synthetic native PostgreSQL tests cover admission/retry/enqueue/claim, idempotent identity, exact hash/owner deletion, cancellation, cascade/missing, rollback, mixed deadlines, actual COMMIT withholding, bounded SQL, worker/write and candidate-set races, row-wait abort, interrupted deletion retry and trusted run/queue quiescence. Ordinary repository behavior is checked separately. Preview repair, attachment metadata/file bytes, historical outbox cleanup, imports, provider/infrastructure copies, global scheduling and full account completion remain parent-stack scopes.
