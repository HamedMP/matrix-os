# Operator Readiness Probe Monetary Budget

Extends DevStack [#3023](https://github.com/HamedMP/matrix-os/pull/3023), FR19/A4, under ENG-432. This covers privileged text-model health probes; ordinary customer inference and owner-funded Jev retain their existing accounting.

## Contract

1. A single authoritative PostgreSQL lifetime wallet covers every enabled caller and Relay replica. Cache/origin/credential changes, restart, UTC rollover and bootstrap replay never reset its allocation, spend or liability. Missing/expired/disabled wallet fails before upstream work. Daily/minute count quotas remain additional rate limits.
2. Each wallet has an immutable instance binding, initialized once and preserved by migration/restart/replay. Strict protocol1 ready requests and callbacks carry the originating Platform’s opaque binding as a precondition; it never selects a wallet, and older strict protocols reject before paid work. Each immutable probe attempt binds protocol version, UUID, reviewed canonical/native model, fixed request fingerprint, pinned price snapshot/version/expiry and maximum liability. It is not an ordinary user balance, promotional grant or monthly allowance.
3. One transaction locks the wallet and attempt, reserves the maximum cost and creates the started execution. Only the caller performing that transition receives `dispatchGranted:true`. Every repeat returns false plus stored status, including lost acknowledgements and changed execution IDs. Changed economic replay fields conflict.
4. Relay constructs only a fixed nonstreaming `ping` with `max_tokens:1`, no caller prompt/tools/token bound. Reuse reviewed native model mapping, Workers request/envelope normalization and existing conservative pricing, including cache-write risk and safety margin. Never depend on fixing Sonnet `count_tokens`.
5. Wallet model policies are explicitly seeded from the reviewed Relay catalog, including integer thousandth-microUSD rates, context/output ceilings, request fingerprint and price-review validity. Begin must match the seeded policy. Finalization recomputes cost from the stored immutable rates/normalized usage rather than trusting a caller-supplied dollar value. New admission requires current pricing; historical pinned snapshots remain usable for settlement.
6. Complete attributable usage settles exact cost and releases only its proven unused hold, even when the health result is negative. Missing/malformed/over-limit usage, timeout, cancellation, lost start/finalize acknowledgement, crash or unknown outcome retains liability. There is no automatic started-attempt refund/TTL release. Unexpected over-bound reports freeze further admission and retain the discrepancy. A later matching attributable finalize may reconcile an unknown attempt without another dispatch.
7. Platform publishes readiness only after reading the authoritative attempt and finding matching committed settlement, successful terminal health and current pricing. Relay's HTTP `ready` flag alone is insufficient. Cache-only reads create no financial state; legacy cache entries are not monetary evidence. No fallback to a legacy paid GET `/ready` is permitted in budget-required mode. Fixed provider requests disable gateway cache and retries (`cf-aig-skip-cache: true`, `cf-aig-max-attempts: 1`) and payload collection; gateway configuration must not silently multiply a one-dispatch liability.
8. Authority and Relay callback APIs require separate configured service authentication, strict schemas, body limits, bounded requests/responses, no redirects, finite deadlines and generic client errors. Workers/browser tokens cannot access monetary callbacks. A remote store uses authenticated bounded HTTP; literal-loopback HTTP is allowed only for the explicit local service/forward placement, otherwise HTTPS is required.
9. Monetary state remains independent of probe cache deletion and versioned by an additive migration scope. Retain immutable attempts and unknown liabilities. Admission has a bounded attempt count per wallet; shutdown drains in-flight operations and only owners close database pools.
10. Feature activation is opt-in. Existing production defaults remain unchanged. Source Relay monetary mode must reject legacy GET before provider dispatch; the immutable serving Sonnet Relay remains Chat-only. Owner-funded Jev must not be redirected to the operator wallet.

## Local allocation and scope

The user delegated probe-budget sizing while the original total authorization remains $10. Choose **$5.25 prospective operator lifetime availability**, not a charge: the existing worst-case estimator needs $4.800012 for one Sonnet probe and approximately $0.235931 for GLM. Actual complete usage releases the difference. Avoid a new optimistic tokenizer or no-cache assumption merely to fit a small wallet.

Keep **$1.00 as a conservative historical probe reserve**, based on a broader read-only usage audit and refreshed before activation. Individual historical probes remain unpriced; it is not an exact attribution and must never be initialized as zero actual expense or advertised as a retrospectively enforced dollar cap. New receipts collect payload-free pseudonymous provider references for future reconciliation. Historical provider-cost verification remains a separate evidence gate.

The intended activated envelope is: customer policy caps **$3.75** (existing alpha/beta/gamma $0.50 each, old pilot $2.25), operator allocation **$6.25 including the $1.00 historical reserve**. Total $10. No refill to existing balances, source balance/spend reset or Main/Dev production-ledger transfer. A newly registered isolated Stage2 test runtime may receive one explicit idempotent test allocation only after matching old-pilot exposure is reduced first; startup never grants it. All customer policies and the wallet expire before the November monthly reset and the existing TLS certificate boundary. Reduce customer exposure and drain/disable all legacy probe admissions before activating the wallet. Registering a later Stage2 runtime reallocates from the old pilot first; it does not add to this sum.

One authority can live on existing Dev loopback while Mac callers use the supported authenticated inward forward. Both Mac and Dev controllers share that authority through the same store contract; no duplicate wallet or reverse tunnel. The old pilot remains a retained historical baseline with unbudgeted probe admission disabled. Active local worktrees keep their identity, data, ordinary Chat Relay and customer caps.

## Acceptance

- Real PostgreSQL independent-pool races cannot overspend or yield two dispatch grants. Exact replays, changed payloads, restart/UTC/cache/origin/token changes and every crash boundary retain correct liability.
- Sonnet and normalized Workers usage settle at pinned rates; missing usage never yields ready. A negative terminal result can still incur known cost. Finalization acknowledgement loss is resolved through authoritative readback.
- HTTP/control-auth negatives reject before spending; old Relay or GET/no-receipt responses never trigger fallback dispatch. Actual old Sonnet Chat routing remains independently usable.
- Shared local/remote stores observe one wallet. Source Platform -> source Relay -> stub upstream -> real PG proves at-most-once fetch, exact settlement and durable replay without a paid call.
- Any target forwarding preserves the explicit Dev route; default Main is never silently selected.
- Actual paid acceptance is bounded, separately recorded and reconciled against this wallet and customer ledgers; stub evidence does not qualify an upstream provider.
