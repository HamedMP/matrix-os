# Matrix development and test isolation ([ENG-240](https://linear.app/matrix-os/issue/ENG-240/ship-fast-ci-priority-linux-queue-and-native-typescript-checks))

Run heavy tests as the invoking Linux owner in transient system services outside the gateway cgroup. `bun run test:isolated` wraps the canonical full unit suite; other existing checks use `node scripts/dev/isolated-test-job.mjs -- <command>`. Target full required qualification under 600 seconds including queue/controller delay; every current check remains required. Reuse results only after proving identical source, toolchain and check inputs.

Require systemd/cgroup accounting, existing passwordless sudo, Node 24+, pinned pnpm 10.33.4, Bun, Bash, Python 3 and jq; unsupported hosts fail closed. Bound trusted commands to min(6 GiB, 45% host RAM), four CPU equivalents reserving one core, no swap, bounded processes and three hours. One owner-wide lock admits one heavy job; queue waits at most two hours within that lifetime. SIGINT/SIGTERM stops the owned unit and descendants. Hide the host user bus and disable fixture-shell startup files. This resource boundary is not an untrusted-code sandbox or a promise of parallel full suites on 16 GiB hosts.

Use one worker and equal MemoryHigh/MemoryMax; two workers exhausted the budget and an 85% soft threshold caused approximately 74% pressure stalls. Release closed DBs from mock histories, timer/transaction closures and mock implementations. Split all 97 customer-VPS cases, including parameterized US cases, preserving every body and adding moved files to the golden gate. Only eight pure cases avoid DB setup; DB cases retain fresh fixtures and cleanup. Preserve assertions, backend, deadlines, coverage and required checks; audit declarations against the immutable baseline. Fixture homes must not read real owner credentials.
