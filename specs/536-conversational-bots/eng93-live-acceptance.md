## Read-only capture tool

Copy `eng93-live-acceptance-context.example.json` to a private evidence directory and replace every placeholder from the approved runtime's observed IDs. The template is deliberately invalid until completed. The runtime must be reached through a reviewed loopback forward; the tool accepts only `http://127.0.0.1:<port>`, no redirects. Obtain an existing bearer session through the approved client flow. Do not mint credentials, read credential stores, change grants, or commit the token. Pass it via `MATRIX_ACCEPTANCE_TOKEN` in the operator's existing session without shell-history literals.

```sh
node scripts/testing/capture-routine-acceptance.mjs /private/evidence/context.json /private/evidence/01-before.json
```

The tool performs only four GETs, each with a10s timeout and256KiB response cap: `/api/system/info` (first; exact `release.gitCommit` must match), `/api/chats/:chatId/bot` (must match Bot ID), `/api/chat-agents/:botId/routines`, `/api/chats/:chatId/bot-tasks?includeRunIds=true`. It saves an exclusive0600 file containing selected routine state, last fire and matching open task/run IDs. The production task route exposes open tasks only: terminal fire snapshots explicitly mark `terminal_task_not_exposed_by_open_projection`; obtain terminal task/run linkage from approved runtime diagnostics separately. Missing in-flight task linkage or mismatched Chat/Bot fails. It omits tokens, prompt/name, messages, accounts and raw server errors. The reported release SHA is installed metadata, not proof of loaded process bytes; independently record worker/service artifact hashes and start times. Missing routine, bad version, errors or oversized data fail. It explicitly outputs `liveQualified:false`: the snapshot needs the timeline, scope records and client captures below. GET snapshots are not approval/control commands and cannot schedule work.
