# ENG-298 — one managed Codex update destination

Owners updating Codex in Terminal should reach the same explicitly promoted CLI as managed consumers. Hermes must retain its private toolchain without silently directing ordinary globals into a second installation.

The installer, shared contract, scope worker and development images promote0.163.0, already qualified by Main's paired protocol records. Exact unknown-version gates stay intact. The helper repairs legacy owner-local npmrc, migrates only a recognized npm Codex shim after the managed binary exists, and retries required reconciliation after partial install failure. Custom commands, owner overrides and old package bytes remain.

For Hermes v0.22, configuration stays outside digest-bound PM tool entries. The active Node/npm paths come from bounded schema1 owner facts, with component validation, realpath containment and symlink rejection. Fresh non-root Matrix owner environments receive a default globalconfig only when the private npm's effective globalconfig is its default. Explicit globalconfig and prefix choices remain authoritative. A five-second/8KiB read-only probe uses no registry/provider request. Root callers skip the probe in both shell and Node; no privilege policy is widened.

Filesystem writes use a same-directory exclusive temporary file, preserved permissions and atomic rename, with cleanup. Existing installer locking covers repair. A failed required repair fails installation for retry; old runtime config is not rewritten. PM package bytes/facts, credentials, authorization, funding, sandbox policy and renderer code are unchanged.

Acceptance: meaningful legacy/PM subprocess tests, exact version/pin coherence, copied-real-PM default/override/digest tests, type/pattern/syntax checks and independent local review. An exact native0.163.0 scope process, Linux isolation, account model catalog and live product surfaces remain separate qualification. No UI captures or live acceptance are claimed. No frontend implementation changes; renderer UI surfaces are N/A, while runtime behavior still requires coordinated live evidence before landing.
