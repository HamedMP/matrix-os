## Implemented behavior

`preview:pair:qualify` reads a canonical ready manifest through the existing
normal authenticated Source profile, creates a new private template and waits
while the operator tests normal-account UIs. Its final Source read fences pair,
generation, source and PR. It does not create a grant, publish a scope, impersonate
a peer, provision a computer or post evidence externally. Private, exclusive,
atomic JSON exports are portable owner-controlled reports outside Git; there is
no new database, credential store, endpoint or authorization authority.

Eight scenarios on Web Desktop/Electron Desktop start as `not_run`. Strict,
bounded observations reject wrong roles, duplicate cases, incomplete step claims,
source drift, future timestamps, raw unknown fields and credential-bearing capture
queries. A claimed live pass needs both screenshot and recording links. Missing
cases stay pending; fixture successes never count as live results. Every human
report requires review; no export synthesizes an authoritative acceptance pass.

`preview:pair:qualify:fixtures` reuses eight retained first-party component and
owner/client/relay/authorization suites, including inherited project prompt
execution. It verifies the actual clean checkout against the requested full SHA,
requires an explicitly selected disposable loopback Postgres and runs the actual
Vitest producer with a bounded report. Every selected file must contain passed
assertions; missing, skipped, empty, duplicate, foreign or inconsistent reports
fail. Candidate tests have a temporary HOME and a small environment without
control, cloud, GitHub or model credentials. This is local execution, not an OS
sandbox; the selected candidate must be reviewed before running it.
