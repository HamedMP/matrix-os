# Contract: Matrix-Funded AI Relay

## Trust boundary

```text
browser/channel
  -> owner gateway (owns Chat, validates owner intent)
  -> Matrix central relay (verifies runtime, enforces funded policy)
  -> Cloudflare AI Gateway (Unified Billing, payload logging disabled)
  -> Anthropic
```

The central relay is the only holder of the funded upstream credential. A customer VPS receives only a runtime-scoped relay credential. The relay ignores client-supplied owner IDs, billing IDs, gateway metadata, base URLs, and upstream authorization headers.

## Implementation checkpoint

The first PR implements the fixed Cloudflare transport, a distinct funded-only HMAC audience, explicit model/path/field/header policy, bounded request/response streaming, global and per-runtime admission, and shutdown cancellation behind a startup feature flag. Owner identity, expiry, per-runtime revocation, recurring eligibility refresh, request correlation, token-aware reservation, and production VPS issuance described below are target requirements for the subsequent activation slices; funded access remains disabled until they land.

## Accepted Anthropic surface

Initial allowlist:

- `POST /v1/messages`
- optional `POST /v1/messages/count_tokens` after an SDK spike proves it is needed

All other paths return `404`/`405`. Query strings are rejected unless explicitly specified. The relay is not a generic forward proxy.

## Request processing

1. Enforce connection/header/body timeouts and a 2 MiB request body limit before parsing.
2. Verify exact audience/scope/expiry/revocation of the runtime credential.
3. Derive `ownerId` and `runtimeId` from the credential; hash them for vendor metadata where raw IDs are unnecessary.
4. Enforce global and per-runtime token-bucket rate limits plus bounded active concurrency. Registries have explicit caps, TTL/LRU eviction, periodic stale cleanup, and shutdown drains.
5. Parse the Anthropic request with a bounded schema sufficient to enforce model, message count, content block, tool, system prompt, output-token, and metadata limits. Preserve SDK-compatible unknown safe fields only through an explicit allowlist/version gate.
6. Reject models not allowed by the current Matrix-funded policy. Owner credentials never pass through this route.
7. Replace authorization, host, gateway metadata, and forwarding headers with relay-controlled values.
8. Add a relay request ID and content-free custom metadata. Set `cf-aig-collect-log-payload: false`.
9. Dispatch to the fixed Cloudflare Anthropic endpoint with `AbortSignal.timeout(10_000)` for connection/first response and a bounded total stream deadline appropriate to Agent runs. Use `redirect: "error"`.
10. Stream with backpressure and maximum event/line/total accounting bounds. Do not buffer the full response for usage extraction.
11. Map upstream errors to the canonical safe envelope. Log provider detail only in redacted server logs.
12. Release concurrency slots in `finally`; abort upstream when the downstream disconnects.

## Header policy

Accepted from the owner gateway:

- funded-audience relay authorization credential (`sk-matrix-funded-*` at this checkpoint);
- `content-type: application/json`;
- a bounded idempotency/run correlation header generated by the trusted owner gateway;
- Anthropic SDK version/beta headers from a fixed allowlist after validation.

Dropped/replaced:

- `x-api-key`, `authorization` destined for a provider;
- `host`, `forwarded`, `x-forwarded-*` except edge-injected trusted values;
- Cloudflare AI Gateway control/metadata headers;
- arbitrary tracing/baggage headers;
- user/account/billing identity headers from the client.

## Retry and caching policy

- No semantic or response cache for Agent SDK messages.
- No automatic retry after response bytes have been emitted.
- At most one retry for a proven pre-response transient failure, only when the operation is safe and the provider/gateway idempotency contract is validated.
- Resume state remains in the owner kernel/Agent SDK. The relay is stateless with respect to conversations.

## Initial safety policy without per-user metering

- funded feature flag defaults off;
- allowlist eligibility cohorts during rollout;
- one dedicated Cloudflare gateway and Unified Billing budget;
- Cloudflare global spend limit as coarse fuse;
- Matrix global concurrency and requests/minute limits;
- Matrix per-runtime concurrency and requests/minute limits;
- model/output-token/tool/message/content limits;
- emergency kill switch refreshed at most every 60 seconds;
- alerts on spend, rejection rate, latency, authentication failures, upstream errors, and concurrency saturation.

This is intentionally not advertised as unlimited. It is an included preview governed by fair-use protections. There is no per-user balance UI until Matrix can enforce it atomically.

## Later reservation hook

Before dispatch, a future `FundedUsageAuthorizer.reserve()` returns a request-scoped reservation. Dispatch occurs only after a transaction conditionally reserves remaining balance. In `finally`, the relay commits/reconciles provider usage or releases the hold. The initial authorizer implements only eligibility/global policy, so adding metering does not change the relay or owner-runtime wire contract.

## Upstream data flow

Prompts, messages, images, tool schemas/results, and file-derived content necessarily flow from the owner kernel through Matrix relay, Cloudflare AI Gateway, and Anthropic for funded turns. Matrix relay does not persist that content. Cloudflare payload logging is disabled. Client UI must disclose this path and distinguish it from owner-direct Anthropic/OpenRouter access.

Operational metadata may include hashed owner/runtime IDs, request ID, requested/canonical model, token counts, cost, timing, response class, and policy version. It excludes content and secrets.

## Shutdown and dependency ownership

- relay startup constructs config validator, runtime credential verifier, policy source, bounded limiter registries, Cloudflare client, telemetry, and later the Kysely repository;
- registration fails immediately if any required dependency is missing;
- only the component that creates a database/pool destroys it;
- shutdown stops admission, aborts/drains active streams within a deadline, clears limiter timers/maps, flushes bounded telemetry, then destroys owned resources;
- a failed subscriber/log sink is isolated and cannot prevent request cleanup.

## Rollback

- Disable `MATRIX_FUNDED_AI_ENABLED`; new funded requests return `ACCESS_DISABLED` within 60 seconds.
- Owner Anthropic profile/key and OpenRouter paths remain available and direct from the owner runtime.
- Revert runtime default selection only for users still on `matrix_included`; never rewrite explicit owner-funded selections.
- Rotate/revoke all relay credentials if the boundary is suspected compromised; do not rotate owner credentials.
