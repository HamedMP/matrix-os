# Canonical Terminal entry and current qualification

Task7c joins real canonical Terminal records to the existing routine source/controller and packaged CLI. Canonical Matrix Bot remains the scheduled executor. This slice is not complete normal Terminal availability: required private native configuration handoff remains Task7d.

## Launch and source availability

The shared Terminal menu exposes Claude Code, Codex, Hermes, OpenCode and Pi across Web Desktop/Web Canvas, Electron Desktop and Web Mobile. A deliberate selection sends only `managedLaunch.harness`; arbitrary command/agent hints cannot request source authority. Hermes readiness checks its actual installed executable/version and does not claim account authentication. Missing Hermes has no fabricated npm install package. Native Mobile does not currently expose this Terminal launcher; its existing receipt/review surface is unchanged.

The trusted interactive-equivalence switch defaults off in production and is not a public field. Unknown native configuration cannot be silently replaced by a stripped safe environment. The all-five fixture matrix does not qualify normal owner environments, real systemd/Zellij, the shipped Linux x64 package or provider accounts. OpenCode Terminal selection is separate from the owner-deferred native6aN Chat adapter.

The existing runtime resource-owner rule still requires one configured owner and retains its Preview resource mapping. Actual routine source owner is the verified JWT/platform principal, never an alias to configured-container or Preview owner. Missing Computer/routine dependency denies source without changing ordinary workload ownership.

## Private admission and currentness

Before any native dispatch, the host allocates its exact public I/O reference and the canonical runtime admits a real reserved tab/incarnation under its existing mutation ordering. Capacity, observer and Zellij-session admission complete first. A same-ID collision rejects reservation; public records cannot be adopted as launch authority. The host then dispatches and holds real supervisor/root/generation proof. Its transitional port denies calls until the exact reserved incarnation and I/O reference are finalized. The Gateway retains that expected association privately and rechecks it on later operations; no temporary Chat/run/task or public-ID proof is fabricated. Source registration is lazy on a real native invocation. Canonical expiry, failed join or current-record invalidation retires the held proof/channel and frees its proof slot without stopping native I/O. Explicit owner action approval, routine activation, background model authorization and integration grants remain separate.

Slow manager verification runs outside database transactions at join, invocation and after an owner wait before capability issue. Periodic manager proof loss revokes the private channel. Locked consume/claim validation checks pinned supervisor/host/root process identity and ancestry, private lifetime/generation and a bounded local read of the canonical atomic record, including incarnation and stop fence. It does not issue a fresh systemctl/UDS request inside database locks and does not claim an exact manager requery at each claim. Existing source-generation/revocation gate and final write checks remain unchanged.

Public I/O references may persist; capabilities and retained principal/proof do not enter argv, native environment, startup command, history or restored session JSON. The workspace principal uses a private weak association and cannot survive JSON copying. Source and owner-action registries retain their existing caps/expiry/drain rules.

## Lifecycle and CLI semantics for public documentation

`matrix`, `matrixos` and `mos routines` keep the same commands/envelopes. `propose --input - --request-id <uuid>` requests a real private target task and pending human approval, never activation. A queued receipt is historical admission, not proof of active schedule or native effect completion. `list`, `show`, `pause`, `resume`, `archive` and `request <uuid>` stay within the confirmed private target. Mutations keep the original UUID; controls require a base revision. Changed payload/target cannot reuse a UUID; archive preserves history and cannot resume.

Caller EOF/extra frames/cancellation revoke the pending owner wait and null the unused capability token. An unknown result retains the original UUID for reconciliation, without automatic retry. Ordinary outer CLI completion ends that call; only the stored consumed capability/receipt can retain an accepted target claim while the parent source/root/current policy remains valid. Root loss before claim denies it; a claimed canonical target intent is independent. No cancellation acknowledgement means effects are known stopped.

Gateway/viewer shutdown drains proof and leaves the native workload/I/O alive. A reserved dispatch stays pending/unknown until its producer settles; it is never reconstructed as a running source. Restore may reattach confirmed live I/O with status unavailable while preserving an unresolved dispatch marker; it never reruns the workload. Explicit stop still attempts the manager stop, but an unsettled dispatch cannot become a confirmed deletion. Its actual record/stop fence remains until settlement or explicit operator recovery, so a possible late dispatch cannot lose its canonical recovery association. After settlement, ordinary explicit stop/delete remains available. Restore reattaches only existing I/O. A manager active state is not native success; exited helper status/exit0 cannot establish native completion or permit ended-native archival. Stopped/unknown host restore stays unavailable even if an old helper pane remains. Explicit workload stop writes a durable fence before manager stop and retains unavailable/native-exit-null on uncertainty. Explicit user deletion after manager-stopped confirmation retains existing deletion semantics for the Terminal record/pane; canonical routine/request/approval/history remains in owner Postgres.

A separate public site documentation PR must use the final availability matrix after required Task7d implementation/review and remaining qualification gates. Do not advertise all five normal Terminal entries as routine-enabled from this slice. Nima capability discovery/skills ownership is unchanged.

Canonical preadmission runs before the host acquires its generation/GC lock, because ensuring the workspace Zellij session may acquire that same lock. No workspace RPC is awaited while holding the host generation lock. Prepare returns the real tab plus a producer-only settlement token on the owning internal call. Completion requires that one-use token bound to the exact incarnation/host; public list/restore records cannot supply it. The runtime keeps at most64 hashed leases for5minutes, sweeps expired entries and drains them on shutdown. Lease loss/expiry/restart or prepare-response loss preserves unknown pending recovery and never reconstructs completion from public IDs. This is launch settlement correlation, not routine, native-account or background authority.

Only lifecycle-produced pre-spawn evidence plus the private producer lease can mark a reservation never-dispatched. That transition removes nativeHost, records failed/native-exit-null and permits ordinary explicit cleanup. Missing descriptor, a method returning, or a currently absent manager unit alone cannot prove absence. Verified native binding or a manager-observed started unit can settle the launch request, without claiming native liveness/exit or effects are stopped. Uncertain dispatch retains pending recovery. Completion consumes the lease before writes, and response loss never triggers a second completion attempt.
