# Terminal routine foundation (Task 7a)

This slice prepares shared process proof, PTY ownership and the ordinary CLI transport. It does **not** register production Terminal sources, change canonical launch/restore behavior, or establish support for any of the five native harnesses. Tasks 7b and 7c remain required by the [approved Terminal design](./terminal-launch-adapter-design.md).

## Internal contracts

- `terminal-writer.c` owns native listener/client descriptors through opaque N-API handles. Linux `SO_PEERCRED` captures the connection creator; `SCM_CREDENTIALS` from **every** `recvmsg` identifies actual writers. Missing/mixed/changed credentials, ancillary descriptors, truncation, invalid UTF-8 and extra frames reject the request. Descriptor transfer does not preserve source proof merely because the original process remains live. Same-UID cooperating processes or hostile debugging are not isolated by this mechanism.
- `process-identity.ts` reads Linux process PID/parent/UID/GID/start incarnation, rejects dead/zombie/privilege-transition observations and repeats bounded ancestry/start observations. A stale saved start test is not a real PID-recycling experiment. Missing procfs visibility fails proof closed.
- `hosted-pty.ts` owns the actual native child. Viewer detach and `closeProof()` do not signal it. Only explicit `stop()` signals the workload and waits for actual exit; timeout reports unconfirmed termination. Zellij must retain canonical screen/history and snapshot ownership; this raw I/O transport is not a screen reconstruction implementation.
- `writer-broker.ts` accepts one strict routine operation per client, proves the writer against the host-held root and continues reading while owner decisions wait. EOF/extra bytes cancel that invocation independently of the parent PTY. The executor callback is internal and must come from the authenticated held launch in Task 7c, never a public request or restored descriptor.
- `routine-source.ts` is preparatory controller wiring. It derives owner from the actual admitted `RequestPrincipal.userId`, keeps Terminal session/incarnation/launch distinct from Chat/Bot identities, and uses the existing source controller plus fixed published CLI/private IPC. Its supplied host/root must come from a real held host launch. Only the real accepted capability/receipt validator may keep an accepted handoff claim valid after ordinary CLI-child exit; current source/root/policy checks still apply.
- `routine-terminal-client.ts` accepts an inherited socket **location**, never owner/harness/source authority. Requests and responses use existing strict schemas. Loss after a mutation may have been sent returns the original request UUID with an unknown disposition; it never retries. A CLI with private parent IPC cannot fall back to the Terminal broker after disconnection.

Caps and cleanup: native descriptors 128; frame 32 KiB; ancestry 64 observations; broker 16 clients including pending cancellation, 5-second initial frame and 120-second action deadlines; PTY 8 viewers with 60-second heartbeat and 256-KiB output backpressure; source 8 active calls, 256 retained invocation records and 30-minute lifetime. Native handles close idempotently, listener paths are removed by the owning broker, and callers own the private directory cleanup after the workload exits. Source/controller shutdown drains bounded children; it must not call workload stop.

## Required subsequent wiring

Task 7b supplies the shared held launch, native host and immutable generation source described in [Terminal host lifecycle](./terminal-host.md). The native writer builder is now invoked by the gateway native build and the host-bundle path stages the complete closure. Source implementation and component tests do not qualify actual systemd transport, the shipped package or full-screen Zellij. Those acceptance gates remain required.

Task 7c must retain authenticated canonical workspace/createTab admission privately in Gateway and match it to the actual held launch. Ordinary Terminal UDS access, caller `agent` hints, startup commands, public restore records and environment owner labels cannot authenticate a source. It must wire all five real builders/readiness paths including Hermes, explicit workload termination and truthful recovery, then test the actual source/controller/fixed CLI/Hono/Postgres path. No inferred `--yolo` permission or fabricated Chat binding is allowed. A lost original proof requires genuine retained reproof or an explicit new launch for authority; original live I/O survives.

## Evidence limits

Actual isolated Linux ARM64 Node 24.21 component probes exercise the compiled native writer and production PTY/broker modules; local Node 24.18 tests exercise the client and negative source boundaries. These are neither shipped Linux-x64 Node 24.18 package smoke nor real systemd transport, full-screen Zellij, native five-harness/account acceptance, or positive Matrix source admission. Those gates remain open. Full CI/coverage/review and the separately tracked public-site documentation PR remain required before final delivery.
