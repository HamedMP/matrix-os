# Terminal host lifecycle (Task 7b)

This slice implements the retained host and immutable package source. It does not enable routines in canonical Terminal routes, add five-harness launchers or expose source availability. Task 7c owns those integrations. Native OpenCode Chat adaptation is owner-deferred independently of the shared Terminal path.

## Authority and lifetime

`createTerminalHostService` is a trusted Gateway-only dependency. Its `start` receives an internal launch and optional private `onBound` callback; it is not an ordinary UDS createTab payload. A strict persisted descriptor contains public launch/I/O metadata only. It cannot contain owner, source, capability, grant or action authority. Task 7c must derive the actual verified principal and retain it in that callback without placing it in the descriptor, argv, environment or layout.

The shared held anonymous-pipe wrapper explicitly selects the distinct Terminal frame schemas; its default Codex protocol is unchanged. The service process owns a child host through Node IPC. The host owns the native PTY and captures its actual host/root/supervisor process incarnations. Before invoking `onBound`, Gateway matches the retained private channel generation and descriptor digest, the exact generation and systemd unit InvocationID/MainPID, current process starts, UIDs/GIDs and lineage. Public names, PID hints and first connectors never replace this channel. The later authority controller must continue validating the captured live source/root for every operation.

EOF, invalid frames, private channel failure, failed binding or an absent native proof module fence routine operations and close their bounded listeners. They do not call workload stop. The host continues I/O while the service holds it independently of Gateway. Restore inspects the persisted I/O reference and unit state only; it does not reconstruct old authority, call `onBound` or relaunch the workload. Fresh authority after original proof loss requires explicit fresh launch. Missing stop acknowledgement returns `unknown` and retains recovery records; only confirmed inactive systemd state is `stopped`.

The fixed `terminal-io-attach.mjs` receives one socket location. It enters/restores raw mode, sends actual pane dimensions initially and on SIGWINCH/resize, forwards UTF-8 input and applies output backpressure. It has no authority or stop command. Zellij retains its existing screen, history and snapshot role. Its canonical pane wiring and full-screen behavior remain required in 7c and package acceptance.

The host retains at most 256 KiB for the first I/O handoff, using one public node-pty backpressure pause at 128 KiB for at most 100 ms. It then keeps draining into the bounded prefix so a missing pane cannot indefinitely suppress native exit notification. The first peer receives retained bytes once and resumes any paused reads; later detach/proof loss does not pause the workload, and later attachments never replay a raw-byte screen. A cap overflow or a pre-attachment backpressured exit is explicitly marked potentially incomplete.

Native exit aborts proof and resolves the native lifecycle independently of final I/O teardown. An early native error/exit can retain only its bounded initial bytes for the first pane for at most 30 seconds; it does not need a live-root binding or source approval to deliver ordinary output. Explicit stop cancels this retention, while source-only proof loss does not. `exited` and final `closed` are distinct. A manager unit can still be active during this bounded handoff; Task 7c must derive native-root status independently and never use manager activity alone as source/root liveness. This introduces no persisted output or VT/history engine.

The I/O-only helper and host service report their own transport/process completion. They do not transport the native CLI exit code: that value is **unknown** at this API boundary, never inferred as zero from successful output delivery. The early-exit probe deliberately has native exit 7 and successful service/attach completion. Before product wiring, Task 7c must carry or truthfully mark native exit status independently of these helper results.

## Bounds and cleanup

The source invocation map reserves/checks its 256-record capacity at insertion after asynchronous validation. End/expiry first abort authority and then clear retained records. Live accepted records are not evicted merely because the CLI child exits. The ordinary real-socket client preserves the original business UUID on uncertain mutations, issues one request and never falls back from disconnected private IPC.

The host channel allows eight pending actions, 16 pending IPC sends, a ten-second admission deadline and two-minute action deadlines. At most 256 cancellation tombstones expire after two minutes, with recurring sweeping and shutdown drain. Only exact late cancelled replies are ignored; unsolicited/replayed completed replies fence the source. The private service queue is bounded at 64 and retained proof channels at 32. **Neither bound is a live Terminal-session ceiling**: excess proof channels close without stopping the new workload or its I/O.

Persistent descriptors have no live-session count cap. A minute sweep reads at most 512 directory entries and 64 valid records using a retained cursor, removes only confirmed stopped records older than 24 hours and skips unknown/live units and retained bindings. Directory checks reject symlinks or foreign ownership; cursor, timers and private channels drain on shutdown. Start/descriptor mutation and sweeping hold the existing cross-process generation-GC lock. Existing GC recognizes the same top-level generation in both legacy and native descriptors and preserves all referenced/current/rollback generations even above its soft retention target.

## Immutable runtime closure

`build-terminal-generation.mjs` uses the existing declared esbuild dependency offline to bundle host, service, attach and protocol code, rejecting external mutable package imports. It copies the exact Node executable, node-pty 1.1.0 JS and native addon, node-addon-api 7.1.x, native writer addon and existing Zellij/keeper/attach assets. Before publishing a generation it executes the copied Node and loads both copied native addons. The manifest records actual Node version/modules/N-API, Linux architecture/libc, dependency versions and protocol version, plus every regular asset's size, mode and SHA-256. No install, download or service mutation is performed by this packer.

Generation identity covers the canonical complete manifest. Validation rejects missing, tampered, undeclared, writable or symlink assets and mismatched runtime metadata. Host/service/attach entries verify they execute the generation's pinned Node. New keeper/attach scripts re-exec that Node after validating their selected closure. Readiness and the existing three-argument updater generation-ID helper validate v2 closure bytes; a damaged v2 package cannot silently fall back to legacy readiness. Genuine old three-asset generations retain their exact historical hash and behavior. Updates do not restart or migrate existing live sessions.

Runtime assets are bounded at 512 files, 256 MiB per file and 512 MiB total. Immutable installation ownership remains part of the host updater's existing trust boundary. A cooperating hostile same-UID process is not an isolated adversary. Runtime loading fails closed for unsupported ABI/architecture/libc; no mutable `/opt/matrix/app` dependency fallback is available.

## Required acceptance still open

Named IPC/systemd-manager fixtures validate internal failure handling, not actual supervisor authenticity. Local native PTY and direct-process Linux component evidence must remain separately labeled from a real nonroot systemd user manager. The required manager lane fails explicitly when prerequisites are absent. Shipped Linux x64 Node 24.18, actual Zellij/full-screen behavior, full host-bundle update/rollback and five native harness/account tests remain distinct gates.

Task 7c must wire authenticated canonical route admission, real current source/controller/fixed CLI/Hono/owner Postgres, exact policy decisions and five launchers including Hermes. It must test pending owner cancellation, accepted receipt versus caller exit and source/root loss without fabricated positive authority. Public documentation remains a separate private site-repository PR under Task 8. No deployment, installation, background grant, native account or production authority is implied by this source slice.
