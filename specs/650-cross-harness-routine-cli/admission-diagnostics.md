# Routine admission diagnostics

An exception from the existing routine runner leaves a fire uncertain with `outcome_unknown`. The previous scheduler warning recorded only an exception name, which omitted the canonical admission error code needed to distinguish failures. This change improves that warning; it does not identify or fix the underlying admission failure.

The existing `[bots] routine outcome unavailable` warning now carries a fixed `errorType` and, only for a native Error with the direct `CanonicalChatOrchestrationError` prototype, a string `code` validated by `CanonicalChatSafeErrorSchema.shape.code`. Unknown or malformed codes are omitted. Generic exceptions use `Error` or `UnknownError`; their caller-controlled names are not copied. Exception messages, stacks, causes, status, provider/account/path/token data and arbitrary fields are never included. Proxy inputs and payloads are skipped before any inspection, including revoked proxies. Only own data properties supply the code, so getters and proxy traps are not invoked and diagnostic classification cannot interrupt uncertain settlement for those malformed inputs.

The scheduler still settles the same fire as uncertain, retains `outcome_unknown`, and does not defer or repeat dispatch after a thrown outcome. No scheduling, retry, cancellation, approval, model/source authorization, integration permission, executor or persistence behavior changes.

`tests/gateway/bots/routine-scheduler-diagnostics.test.ts` drives the actual scheduler tick through a rejected runner with isolated repository boundaries. Its first Red is the original class-name-only warning missing the canonical code. Review also reproduced a diagnostic regression where proxy introspection escaped before settlement; a separate Red covers throwing/revoked proxy payloads and inputs, then requires no trap execution and the same uncertain receipt. The suite checks malformed/accessor payloads, coarse fallbacks, bounded output and no replay. These tests do not invoke a provider or establish live routine acceptance. Existing scheduler tests retain normal execution, explicit capacity retry and shutdown coverage.
