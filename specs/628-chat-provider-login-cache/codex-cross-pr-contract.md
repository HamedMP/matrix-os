## Public interface and sequencing

1. `packages/gateway/src/ai-providers/provider-workflow-native.ts`: optional synchronous `onLoginSucceeded(harness: "claude" | "codex"): void`. The native producer must await accepted canonical native completion before notifying, and notify before public `succeeded`. Proof rejection, unsupported starts and cancellation/failure before canonical acceptance do not notify. Cancellation after canonical dispatch preserves the actual completion outcome; a confirmed success is not relabeled as a failed login.
2. `packages/gateway/src/server/native-provider-workflow-runtime.ts`: binds this callback to configured `ownerId`, never a receipt-supplied owner. `packages/gateway/src/server.ts` supplies `invalidateNativeLoginCatalog` from the runtime catalog composition.
3. `packages/gateway/src/chat/runtime-provider-catalog.ts`: `invalidateNativeLoginCatalog(ownerId, harness)` synchronously evicts only the corresponding owner/native model source and `codingProviders.invalidate(ownerId, harness)`. It performs no provider/model call. The registry retains its existing synchronous credential-detection cache invalidation; no new renewal or background task is added.
4. `packages/gateway/src/chat/codex-model-catalog.ts`: `source(provider, principal?)` plus `source.invalidate(principal?)`. Owner entries retain the existing success/failure TTLs with a 64-entry FIFO bound. Target invalidation deletes positive/negative state. Old in-flight results cannot populate a replacement entry; new discovery waits for the older process to be reaped. An unconfirmed-child-exit fence is never cleared by login. Different gateway/runtime instances own separate source objects.
5. `packages/gateway/src/coding-agents/provider-registry.ts`: health remains keyed by exact owner/provider. Bounded request tokens prevent pre-invalidation health from overwriting newer cached health, for both old failure and old success. Owner matching does not use a prefix that could delete a sibling owner's cache.
6. `packages/contracts/src/provider-workflows.ts`: existing `ProviderWorkflow`/V2 DTO. It carries workflow ID, exact harness, kind, state and V2 option; it does **not** carry owner, Computer UUID or `authGeneration` authority. No new public event field is needed.
7. `packages/ui/src/agents-providers/use-harness-workflow-controller.tsx` → `AgentsProvidersView.tsx` → `types.ts` → `provider-settings-controller.ts`: preserve the successful receipt argument through `onRefreshAfterLogin(receipt)` → `onRefreshForConnection(receipt?)` → `refreshForConnection(receipt?)`. For a known succeeded login, notify Chat before awaiting the advisory non-forced Settings read. Login failure/cancellation is different from an advisory read failure after already-confirmed success: the latter must not suppress catalog observation.
8. `desktop/src/renderer/src/features/settings/AgentsProvidersAdapter.tsx`, `provider-workflow-transport.ts` and `lib/provider-settings-identity.ts`: keep the current transport/lifetime guard. The identity is `[status, handle, userId, platformHost, runtimeSlot, authGeneration]`, with null handles/users encoded as `none`. It has no `machineId`; selected Computer/server admission remains the authenticated transport's responsibility. The synthetic handle-change case is not a real Computer-UUID routing test.
9. `desktop/src/renderer/src/features/chat/provider-catalog-invalidation.ts` and `provider-catalog-cache.ts`: accept only a succeeded login for a known harness in the current identity; deduplicate the nonsecret receipt; map `codex` to native Codex driver routes; suspend only affected routes and read with `force=false`. Preserve explicit refresh priority and identity/epoch fences. Already-mounted `useChatProviderCatalog` consumers can observe newly available routes without reopening; gateway admission still decides whether a send is allowed.

The ENG-268 owner explicitly accepted this typed seam and independently added its Codex producer notification. Resolving the overlapping `provider-workflow-native.ts` file by taking either whole side would lose part of the contract.
