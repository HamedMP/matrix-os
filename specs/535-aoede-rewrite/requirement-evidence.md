## Review record

Two structured review passes ran over the implementation:

- **Pass 1** (backend/spec/UI reviewers) — findings fixed: cancel CAS race → `tryTransition` + bounded retry + `"unknown"` outcome; silent WS cancel drops → always-ack `action.cancel_result` (`unavailable`/`unknown`); forged voice provenance on typed requests → normalized to `source:"typed"` with `executionPolicy`/`voiceSessionId` stripped; readiness timeout clamp; startup reconciliation detached; `synthesisSource` probe gating; `identityFor` action-ID validation; `ProviderCatalogUnavailableError`→503 mapping; selective reconnect teardown (`not_found`/`session_conflict` only); operation-label clamp to `maxOperationLabelChars`; SSE timeout aligned to canonical 5-minute envelope; `openResult` accepts `actionArtifacts`; device-setter failures surfaced; palette invoker `data-aoede-dialog`; stale `VocalPanel` doc reference removed.
- **Pass 2** — three reviewers (adversarial backend, requirements coverage, UI/client). Findings fixed: (a) `session-pipeline` no longer escalates a returned `"unknown"` cancel to a session-level `session_conflict` — the `action.cancel_result` ack carries the per-action truth and a live session is not falsely presented as failed; thrown cancellations still emit retryable `chat_unavailable`; (b) `engine.reconnectSession` failed-branch now runs all fallible work (chat-event subscribe, `armTimers`) before committing state — a throwing restore can no longer wedge the session as a zombie "reconnecting" with no subscription/timers, and the regression test proves a later retry fully revives it; (c) fixture payloads renamed to the real canonical inventory (`matrix_list_apps`/`matrix_inspect_app`/`matrix_search_workspace`/`matrix_open_app`/`matrix_apply_app_files` @ `canonical_apps_v1`/`codex_canonical_v1`) with a pinning test that fixture toolIds/revisions equal the production constants — otherwise `toOperationView` would never project fixture result detail; (d) `AoedePanel.canCancel` fails closed when omitted and `AoedeProvider` passes `snapshot.canonical.canCancel`; (e) duplicate "Cancel generation" affordance deduplicated (canonical `CancellationCard` owns it when cards render); (f) fixture backend gained `forceActionCancellation:"unknown"` plus `requested`/`unknown` assertions; evidence screenshots regenerated (30/30).

All fixes carry regression tests in the suites listed above.

Strict follow-up review against the handoff found and repaired: qualified clarification being rejected by the coding adapter; cross-app/traversal result projection; stale media acquisitions; post-dispatch cancellation affordances; device-loss default fallback; deferred sink failures falling through to default output; missing consequential fake composition; and missing real-worker crash evidence. A second focused pass found oldest-first bounded operation history, blocked queued playback after explicit output recovery, and stale device setter failures. These now have discriminating regression cases, including tied timestamps and slow capture cleanup. The screenshot gate rejects malformed schemas and missing fake seams. Mock surface images are labeled as isolated-host evidence rather than full-shell integration.
