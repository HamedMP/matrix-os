# Connected starter

This portable Vite/React application supports the 24 first-party gallery definitions. It starts empty and uses the app-scoped `MatrixOS.db` bridge for owner PostgreSQL records. It contains no customer data, credentials, sample records, browser persistence or direct service execution.

The installer writes its validated definition to `src/definition.json` and replaces the single `__MATRIX_APP_DEFINITION__` placeholder in built `dist/index.html` with JSON escaped for `<` and Unicode separators. The installed source remains rebuildable without monorepo imports. Source builds use the source definition when the placeholder is still present.

Views include a currency-separated settlement chart and ledger, travel itineraries, dated agenda, definition-specific status boards, libraries, notes, seven-day habit check-ins and a focus timer. Subscriptions separates active recurring costs by currency and cadence; Cashflow separates sent/overdue receivables from paid funds. Only saved records contribute metrics. Unknowns are nullable; unpaid, refunded and pending amounts do not count as settled funds. Manual edits are recorded in `manualFields`. Archive preserves the payload in owner storage and hides it from normal reads and exports.

The connection inventory parser has one dependency-free canonical source in `packages/contracts/src/app-gallery-inventory.ts`, with generated portable snapshots used by this kit and App Gallery. Repository builds refresh the snapshots; installed owner builds retain them when the monorepo is absent. Both clients accept up to 2,000 entries and reject malformed inventories as unavailable.

Connect & import reads the owner integration inventory, requires exact, unambiguous active account labels and bounded dates, and requires context for repository/project/channel/document sources. It submits a read-only request through `MatrixOS.generate`. The UI says a request was sent, never that an import completed. Check records reloads saved data; imports must deduplicate source IDs, preserve manual fields and report coverage. `MatrixOS.service` is not called.

Web Canvas, Web Desktop, Electron Desktop and Web Mobile provide the existing Matrix bridge. Native Mobile currently loads a raw app-session URL without that bridge; the kit presents a precise message to use a supported view, disables save/import actions, and does not claim that unknown records are empty.

Save/archive failures retain records and drafts, with stable draft IDs on retry. Existing-record saves and archives use `MatrixOS.db.compareAndSwap(table,id,expectedPayload,{payload})` with the originally read raw payload. Concurrent imports, edits and archives cause a visible conflict instead of overwriting a draft or resurrecting archived data. Computers without this atomic operation fail closed for existing-record writes. Lost insert responses are reconciled through `findOne` only when the same intended record already exists. Internal `basePayload` and `rowId` metadata never enter stored payloads or exports. Confirmed mutations invalidate older reads. CSV exports contain the filtered record fields, escape quotes and neutralize spreadsheet formula prefixes. Source evidence links allow HTTPS without embedded credentials. Reads scan at most ten pages of 500 rows, skipping archived records and accumulating at most 1,000 active records. The UI explicitly discloses incomplete coverage and limits charts/exports to displayed records. Records retain caps of 100 evidence entries per record and 16 source accounts; these limits bound the portable workspace.

From this directory use `pnpm install --frozen-lockfile` then `pnpm build`. Host packaging builds the kit once with `node scripts/build-app-gallery-template.mjs`; installers copy compiled output without running caller-provided commands. Behavioral tests live in `tests/default-apps/connected-starter.test.ts` and `tests/default-apps/connected-starter-records.test.ts`. The kit does not provide automatic schedules or organization sharing.

Revenue points and labels share one scrollable plot coordinate system, including narrow viewports.
