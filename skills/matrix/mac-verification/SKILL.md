# Mac Verification

Use the current Chat's isolated Matrix OS worktree. The user describes the change or asks to verify existing changes; never ask them to find a checkout directory, worktree ID, recipe name, or verification command.

1. Confirm the admitted execution root is the current task's isolated worktree. Inspect its HEAD and existing diff before editing. Preserve existing edits; stop if the task is not bound to an isolated worktree. Never change the installed Main runtime or its services.
2. If the user requested a change, implement it in that worktree with appropriate tests. If the user only selected this Skill, inspect and test the current changes without inventing a new change. Keep trial edits uncommitted and report exactly which files changed.
3. Check whether the native verifier supports the resulting snapshot. Current operations are Sign-in and Files Trash/Undo. Choose the named check for an unchanged custom task. The default inspection checks sign-in, and a single plain-text label edit selects the matching recipe automatically. Arbitrary feature diffs, backend changes, mixed edits and generic Mac GUI control are not supported by these recipes. Explain unsupported scope honestly; do not substitute a sign-in screenshot for another task.
4. Run the relevant checks in the cloud worktree, including `git diff --check`. For sign-in use `tests/desktop/signin-device-auth.test.tsx`; for Files use `tests/gateway/trash.test.ts`. Locate the existing Node 24+ runtime and verify `node --version` before running tests or the candidate CLI. On a Matrix VPS, check `${MATRIX_NODE_PREFIX:-/opt/matrix/runtime/node}/bin/node` and prepend that directory to PATH for the command only when needed. Do not replace host tools, change global PATH or install dependencies outside the worktree. Use the repository's pinned pnpm and report real results, including failures. Read errors before retrying; do not fabricate passing checks.
5. Finish this agent turn with the change and test summary. When this Skill was selected in Matrix Electron Desktop, Matrix waits for this exact admitted run to complete, independently reads the worktree snapshot, prepares matching temporary Mac source, installs frozen-lockfile dependencies in a private cache and runs the matching native verification. First use needs network access to the fixed package registry; it never uses the owner's package-manager credentials or configuration. When that native continuation is supplied, do not also queue a CLI request. In an agent or Terminal on the same Matrix Computer without that native continuation, choose the supported recipe from the actual source and run `matrix mac verify --current --recipe sign-in` or `matrix mac verify --current --recipe files-trash` as the final action before completing this turn. The command derives the unique active private Chat and registered worktree from authenticated metadata and the real Git root; ambiguity or a stale context must stop, never guess IDs. Check the installed CLI help for `--current` first. In a candidate checkout whose installed Main CLI predates this command, use `node packages/sync-client/bin/matrix.mjs mac verify --current --recipe <supported-recipe>` from this same repository with its pinned Node runtime; do not replace the Main CLI or restart services just to run the candidate. Do not invoke a local folder picker, invent a preview marker, or manually paste a result receipt.
6. The paired Mac asks once in Supervised mode. A Mac explicitly paired for Chat Full Access can execute while Full Access remains selected in this same Chat without another dialog. This Skill cannot grant permissions. Stop, device revoke, sign-out or changing the active Chat cancels pending work.
7. Matrix automatically attaches the preview screenshot, exact source provenance and native test outcome to this Chat. Acknowledge that receipt separately from your cloud test results. Do not claim native verification passed before the receipt arrives. Preserve trial edits until the user requests rollback; restore only your own edits when requested.

The automatic native continuation requires the requesting Chat to remain open on the paired Mac in Matrix Electron Desktop. An agent in the current Matrix Computer may queue its exact active run through the bounded `--current` CLI; the Mac receiver consumes it only after that same run completes and the source is unchanged. A regular Terminal without a unique active owning Matrix Chat is not an implicit authority; explicit completed-run CLI bindings remain available. Web Desktop and other harnesses still need the originating private Chat open on the paired Mac to receive the request. A missing pairing, source kit or supported snapshot is a real setup/unsupported state, not a successful verification.
